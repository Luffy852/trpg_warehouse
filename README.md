# TRPG 模组库 · trpg-warehouse

一个**公开只读**的网页版 TRPG 模组资料库。把整理好的模组——主控台 HTML、`.xmind` 思维导图，以及原文与地图等资源——托管到对象存储后，访客点开卡片即可在浏览器里查看导图和模组原文，不需要安装客户端，也不需要登录。

仓库：<https://github.com/Luffy852/trpg_warehouse>（Public，`main`）。站点与资源分别由 `warehouse.finewinginnovation.cn` 与 `warehouseasset.finewinginnovation.cn` 提供。

---

## 1. 它能做什么

| | 访客 | 上传者 |
|---|---|---|
| 入口 | 公开，无需登录 | `/upload`，由 Cloudflare Access 保护 |
| 可以做 | 浏览分类卡片 → 条目页 → 打开「思维导图」或「主控台」 | 上传 / 更新 / 上架 / 下架 / 删除条目、手动校准容量 |
| 不可以做 | 搜索、评论、编辑、下载资源包清单 | 修改 slug、自动同步或自动翻仓库 |

**几个关键设计**

- **两级呈现**：首页按规则体系分区，卡片只显示封面与模组名；点进条目页才给出两个入口。资源包不是浏览端可见实体，不列清单、不推送。
- **导图在浏览器里看**：`.xmind` 由访客浏览器直接读取、解 ZIP、渲染成只读画布；不跳下载、不依赖本地 XMind、不生成第二份 HTML/SVG 副本。
- **主控台原样托管**：成品 HTML 及其内部相对链接、iframe、图片按上传时的目录结构原样保留，站点不重绘、不改写引用；导图解析失败时仍给「下载原文件」兜底。
- **上架即生效，不触发构建**：资源写进对象存储、索引写进数据库，浏览端拉一次列表 API 就能看到新卡片；只有改代码才需要重新部署。
- **草稿与发布分离**：`draft` 不出现在公开书架；管理台可一键上架 / 下架，删除需手打 slug 二次确认。

## 2. 访客端功能设计

### 2.1 首页与条目页

- 首页按 `system` 分大区（DND / COC / 其他），DND 下再按 `kind`（战役 / 模组 / 遭遇）细分；分类由上传者人工判定，不做自动推断。
- 卡片为 3:4 竖版封面 + 模组名，桌面一行 5 张、中等屏 3 列、窄屏 2 列；无封面时用规则名占位。
- 条目页**只有两个入口**：「思维导图」与「主控台」，都在新标签打开。入口 URL 由索引里的两个原始文件名拼出，不硬编码文件名。
- 全站无搜索框、无文本输入、无登录 / 评论 / 用户系统；条目多了靠分类点击查找。这是明确的需求边界，不是待补功能。

### 2.2 思维导图预览

1. 预览页通过 CORS GET 读取对象存储上的 `.xmind` 原文件。
2. 浏览器内解 ZIP：优先 `content.json`，无则回退 XMind 8 的 `content.xml`；占位「请升级」XML、损坏 / 加密文件直接给可见错误。
3. 转成节点树后由 `mind-elixir` 渲染只读画布；一打开自动适配屏幕，支持 `Ctrl / ⌘ + 滚轮` 缩放、拖动平移、折叠与多 sheet 标签切换。
4. 任何失败都显示错误原因 + 「下载原文件」链接，不留白屏。

> 这是**结构可读预览**：节点树、标题、折叠、缩放、平移、多 sheet 可靠；主题色、标记、关系线、外框、概要、嵌入图片等可能简化，不等同 XMind 客户端 100% 还原。

### 2.3 草稿预览

上传者可在受保护的 `/upload/` 下打开草稿预览壳：与正式条目页同形态，但数据源换成包含草稿的全量账本；导图预览复用同一份前端代码，只是直取对象存储原文件而非公开下载接口。

## 3. 上传与管理功能设计

### 3.1 三区输入

| 区 | 内容 | 落位 |
|---|---|---|
| ① 主控台单文件 | 成品 HTML | `modules/<slug>/<原始文件名>` |
| ② 思维导图单文件 | `.xmind` | `modules/<slug>/<原始文件名>` |
| ③ 资源树 | 文件夹拖拽或点选，含任意层级子目录 | 剥掉所选顶层文件夹名，其余整树原样挂在 slug 根下 |

另可填元数据（标题 / slug / 规则 / 体量 / 状态 / 简介 / 封面）与可选本地封面。`slug` 为英文小写短横线，是条目唯一 ID，上传后不可改。

```
本地：资源包/assets/maps/深层/地图 01.png
存储：modules/frozen-malice/assets/maps/深层/地图 01.png   ← 不挂「资源包/」这一层
```

### 3.2 上架前校验

- **不预设必备文件名清单**：只解析主控台 HTML 里实际引用的本地路径（链接 / 图片 / iframe / 脚本 / poster 等），逐项求包含；绝对外链保持原样、不纳入断言。
- 路径不安全、两单文件同名、单文件与资源树同名、树内自身重名、缺任一被引用文件、非法枚举 → **拒上架并回执，索引不变**。
- 与两个单文件完全同名的资源树项显式跳过并在回执里写明，不静默丢弃。
- 同 slug 已存在时默认拒绝覆盖；勾选「模组更新」才允许覆盖（含草稿），勾选但 slug 不存在仍按新建处理。

### 3.3 一次上架发生了什么

1. 上传端本地预检 → `/api/upload/prepare`：Worker 校验元数据、路径、依赖与成本闸门，先记 `upload_locks` 预留量，再为每个对象 key 签预签名 PUT 并回一次性令牌。
2. 浏览器并发直传对象存储，大包不经过 Worker 请求体。
3. `/api/upload/finalize`：Worker 用 `head()` 逐个追到真实写入并复核字节数 → 写索引 → 写后读回断言 → 释放预留量。
4. 上传端**重新拉一次公开列表做行为断言**：新建判「卡片 +1」，覆盖更新判「卡片数不变、内容已更新」，状态 draft↔published 变化时按旧状态算 ±1；通过才显示成功。

### 3.4 管理台

受 `/upload/` 保护的全量账本（含草稿），五列纵向列表：模组名 / slug（只读）/ 规则及体量 / 状态 / 操作；按体系序 → slug A→Z 排列，不分页、不搜索。

- **上架 / 下架**：只改 `status`，不重传文件、不删对象、不动容量账、不等构建。
- **删除**：不可逆，需手打 slug 确认（Worker 再验一次）；先清 `modules/<slug>/` 下全部对象，成功后才删资料卡；中途失败保留资料卡可重试。删除不划账。
- **校准**：人手动点一次、当场翻一次 `modules/` 前缀，真删无索引的孤儿对象，再把账本对齐真实占用、清陈旧预留、写静态快照。页面访问只读该快照，**绝不自动翻仓库**。
- **草稿**：不是保密状态（对象存储公开只读），只是没挂到公开书架。

## 4. 技术方案

### 4.1 架构

```
访客浏览器
  ├─ 首页 / 条目页 / 预览页 / CSS / JS  → Workers Assets 边缘直出（不跑 Worker）
  ├─ GET /api/modules                  → Worker 读 D1（只返回 published，不含资源清单）
  └─ 预览页 fetch .xmind               → R2 自定义域（CORS GET）→ 浏览器解 ZIP → mind-elixir 只读画布
                                          ↑ 完全不经过 Worker、不生成第二份产物

上传者浏览器（/upload，Cloudflare Access 保护）
  ├─ POST /api/upload/prepare   → Worker：契约校验 / 重名 / 路径安全 / 按主控台实际引用逐项断言
  │                               → 成本闸门 + 预留量 → 对每个 key 签预签名 PUT、回一次性令牌
  ├─ PUT <R2 S3 端点>           → 浏览器并发直传，大包不经 Worker 请求体
  └─ POST /api/upload/finalize  → Worker：head() 追到真实写入 → 写 D1 → 写后读回 → 行为断言
```

**技术栈**：单 Cloudflare Worker（Workers Free 仅允许 1 个）+ Workers Assets 静态壳 + R2（资源）+ D1（索引唯一真值）+ Cloudflare Access（写口）；`aws4fetch` 预签名、`zod` 契约、`jose` 令牌；前端 `fflate` / `mind-elixir` / `@mind-elixir/import-xmind` 全部在浏览器运行；`esbuild` 打包、`TypeScript` 类型检查。

`shared/` 是跨 Worker、上传端、预览页与测试共用的**唯一口径出处**（枚举、路径规则、依赖解析、xmind 格式判定、成本闸门、管理台口径与前端工具函数），避免各端各写一份。

### 4.2 索引与资源

- **D1 是唯一索引真值**：一条目一行，字段来自上传表单；主控台 HTML 不是索引源，也不另养 `modules.json`。
- **R2 没有目录对象**，目录只是 key 前缀；资源基址由 slug 现场推导，不落库、不养派生副本。
- 共用桶场景下，列举 / 删除 / 算规模**一律只碰 `modules/` 前缀**，前缀外对象不碰、不计入本项目规模。

### 4.3 成本与稳定性边界

R2 没有原生硬性账单上限，Cloudflare 的支出管理也不覆盖 R2，所以成本控制在写口自己做：

| 机制 | 做法 |
|---|---|
| 体积闸门 | 单文件 50 MB / 整条目 200 MB / 单条目 500 文件；`finalize` 用真实 `head().size` 复核声明值 |
| 容量闸门 | 本项目 `modules/` 部分自限 **5 GB**（配置 / 代码缺省 / 上传端产物三处同步），按 D1 `total_bytes` + `upload_locks` 预留量聚合 |
| fail-closed | 数字不可信、旧令牌缺成本字段、`head().size` 不可用 → 503 / 413 拒绝，绝不「算了放行」 |
| 预留量只增不减 | `prepare` 先记账再签 URL；中途放弃留下永久预留，宁可高估提前拦死，也不少算 |
| 一键熔断 | `WRITES_ENABLED = "0"` → 写口立刻 503；配合停用 R2 自定义域可整体停机 |
| 零定时遍历 | 无 cron / alarm / `setInterval` / 每次请求查用量 / 自动校准；容量核算只在人触发的写口做 O(1) 聚合 |
| 边缘防刷 | R2 自定义域 + Cache Rules + WAF 限流 + 账单告警；`r2.dev` 不支持缓存与 WAF，不用于对外 |

**不承诺 100% 零费用，也不承诺无需人工干预**：恶意刷自定义域且持续制造缓存未命中，理论上仍会累积 Class B 请求。设计原则是「宁停不烧钱」——数字不明时停止写入，而不是继续跑。

> 5 GB 是本项目自己记的账本闸门，**不是云端硬隔离**；R2 Free 额度按整个桶计算，共用桶里其它项目的用量需各自守住。

### 4.4 安全边界

- 浏览端公开只读；唯一写口 `/upload` 与其 API 由 Cloudflare Access 保护，Worker 内再验一次 JWT 断言。
- 不使用 Worker 的「Enable Cloudflare Access」一键开关——它会连公开浏览端一起锁上。
- `/api/modules` 只返回已发布条目，不含资源包清单；管理台信息不出现在前台。
- 所有 JSON API 分支都 `return await`，保证异步错误落成 JSON 错误响应，而不是平台错误页。

部署与验收步骤只写在 `docs/部署指引_纯点击.md`；本文档只介绍功能设计与技术方案。

## 6. 设计取舍：明确不做

| 不做 | 原因 |
|---|---|
| 中文搜索 / 全文检索 / 搜索框 | 纯点击-查看型站点，条目靠分类点击查找 |
| 登录 / 评论 / 用户系统 | 浏览端公开只读，只有上传者需要身份校验 |
| 浏览端列资源包清单、主动推送资源文件 | 资源入口只在主控台内部，列清单会让条目页退化成资源管理器 |
| 摊平 / 重命名拖拽树、上传时重写 HTML 引用 | 保持整理时的目录格局与成品 HTML 原样 |
| 在 Worker 里解 xmind、上传端导出 HTML/SVG 副本 | 解析放访客浏览器即可，原文件保持唯一真值，不养派生产物 |
| 可编辑预览、写回 | 公开只读 |
| 定时 / 自动校准、写口实时对账、自动翻库 | 成本机制自身零高频开销；容量只在低频写口核算，校准只能人点一次 |
| 改 slug | D1 改 slug 不会搬 R2 对象，会导致全站链接 404；改名走「模组更新」覆盖，换 slug 需删除后重传 |
| 生成第二份索引清单、把资源基址落库 | 索引真值唯一，派生值不存副本 |

CSS 改版后边缘缓存需要手动 purge 一次；本项目不引入版本号查询串，避免牵动所有 HTML 引用。样式改动变频繁时再按扩张型重新评估。
