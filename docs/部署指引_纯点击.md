# trpg-warehouse · 纯点击部署指引

> **适用**：仓库已建立 `https://github.com/Luffy852/trpg_warehouse`（`main`，Public），**尚未部署到 Cloudflare**。
> **承诺**：全程在浏览器里点、在网页表单里粘贴，**不需要打开终端、不需要装 Node、不需要 clone、不需要任何 `npm` / `wrangler` / `git` 命令**。
> 唯一需要"打字"的地方是：GitHub 网页编辑器里替换 5 个配置值、Dashboard 里粘贴几段文本（SQL / JSON / 密钥）。
>
> 详细步骤只写在**这一份文档**里；`README.md` 只做索引，避免两份说明不一致。

---

## 总览（先看这一张表，心里有底）

| 阶段 | 在哪个网页 | 做什么 | 产出 |
|---|---|---|---|
| 0 | GitHub | 上传补丁包（同名替换） | 仓库配置更新 |
| 1 | — | 准备一张「值清单」 | 心里有数 |
| 2 | Cloudflare Dashboard | 建 D1 / R2 / **R2 自定义域** / R2 S3 token；停用 r2.dev | 5 个待填值 |
| 3 | Zero Trust | 设 team domain + 建 Access 应用 | 2 个待填值 + 1 个域名 |
| 4 | GitHub | 网页编辑 `wrangler.toml`，一次填 5 个值 | 配置就绪 |
| 5 | Workers & Pages | Create application → 连 GitHub → Save and Deploy | 站点上线 |
| 6 | Worker → Settings | 加 3 个 Secret → Deploy | 写口可用 |
| 7 | D1 → Studio | 粘贴建表 SQL（**含 `total_bytes`**）→ Run all | 索引表 + 容量锁就绪 |
| 8 | R2 / zone / Billing | CORS + **Cache Rules / WAF 限流 / 防盗链 / 生命周期 / 账单告警** | 预览直传可用 **+ 成本控制闭环** |
| 9 | Zero Trust | 校准 Access 应用域名（AUD 不变） | 登录闭环 |
| 10 | 浏览器 | 按验收清单点一遍 | 完成 |

**为什么必须改 `wrangler.toml` 而不能只在 Dashboard 里点绑定**：Workers Builds 每次从 GitHub 部署都以仓库里的 Wrangler 配置为唯一真值，Dashboard 里手加的 D1 / R2 绑定和环境变量会被下一次部署覆盖掉。`secrets` 是例外，Dashboard 加的会保留。

> **B1-3 成本口径**：R2 没有原生硬性账单上限（Spend Management 只覆盖 Workers / Durable Objects），第 8 步不是可选项。第三方建议的逐条核实与取舍见**附录 A**；结论是「Worker 代理 R2 借 Workers 硬上限」这个前提不成立，真正有效的是**减少回源读取 + 在写口卡住容量**。

## 第 0 步 · 把补丁包同步到 GitHub

1. 打开 <https://github.com/Luffy852/trpg_warehouse>。
2. 点 **Add files → Upload files**。
3. 解压交付的 `trpg-warehouse_成本控制补丁包.zip`，**进入 `trpg-warehouse/` 里面**，把里面**全部内容**（`worker/src/`、`shared/`、`web/assets/`、`web/vendor/`、`migrations/`、`scripts/`、`docs/`、`wrangler.toml`、`README.md` 等）一起拖进上传区。
   - 不要连最外层那个 `trpg-warehouse` 文件夹一起拖，否则会多出一层目录。
   - 同名文件会显示为 modified，这是正常的替换；新增文件（`shared/cost.js`、`shared/cost.test.js`）会显示为 added。
4. Commit message 填 `feat: B1-3 成本控制闸门`，点 **Commit changes**。

> 这一步只是把代码与文档换成 B1-3 版，**不需要填任何真实值**；真实值在第 4 步统一填。
> ⚠ **成本闸门是跨文件的，必须整包替换**：至少要有 `worker/src/index.ts`（写口闸门）、`worker/src/schema.ts` / `token.ts` / `types.ts`、`shared/cost.js`、`web/assets/upload-app.js` + 重新生成的 `web/vendor/upload.js`（上传端送 `sizes`）、`migrations/0001_init.sql`（`total_bytes` 列）。少任何一个都会出现「上架 413」或「no such column: total_bytes」。

## 第 1 步 · 值清单（先把这张表看懂，后面只是往里填）

后面所有"复制粘贴"都是为了凑齐下面这几项。建议开一个记事本（或密码管理器）临时记一下：

| 编号 | 值 | 从哪复制 |
|---|---|---|
| ① | D1 `Database ID` | D1 数据库详情页 |
| ② | R2 公开读基址 | R2 → bucket → Settings → Custom Domains |
| ③ | Cloudflare `Account ID` | Dashboard 右侧栏 / 账户首页 |
| ④ | Zero Trust `Team domain` | Zero Trust → Settings → Team domain |
| ⑤ | Access `AUD Tag` | 应用 Overview → Application Audience (AUD) Tag |
| ⑥ | 站点域名 | Workers Builds 部署后给的 `*.workers.dev`（或你自己的自定义域） |
| S1 | R2 S3 `Access Key ID` | 创建 R2 API token 时 |
| S2 | R2 S3 `Secret Access Key` | 同上（只显示一次） |
| S3 | 一个随机长字符串 | 密码管理器生成，作为 `UPLOAD_TOKEN_SECRET` |

> 分流记一下：**①–⑤ 写进 `wrangler.toml`**（第 4 步，5 处 `REPLACE_*`）；**⑥ 站点域名不写进 `wrangler.toml`**，用在第 3 步 Access 应用与第 8 步 CORS；**S1–S3 只在 Dashboard 里加 Secret**，绝不写进公开仓库。

## 第 2 步 · Cloudflare Dashboard 建资源

### 2.1 复制 Account ID → ③
登录 <https://dash.cloudflare.com>，在账户首页 / 右侧栏找到 **Account ID**（32 位十六进制），复制。

### 2.2 建 D1 数据库 → ①
1. 左侧 **Storage & Databases → D1 SQL Databases → Create database**。
2. 数据库名填 **`trpg-warehouse-db`**（必须和 `wrangler.toml` 里的 `database_name` 完全一致），选位置后 **Create**。
3. 进入数据库详情页，复制 **Database ID** → ①。

> 先不要建表，建表在第 7 步（同样在网页里粘贴 SQL）。

### 2.3 建 R2 桶 → ②
1. 左侧 **R2 Object Storage → Create bucket**。
2. 桶名填 **`trpg-warehouse-assets`**（必须和 `wrangler.toml` 里的 `bucket_name` 完全一致），**Create bucket**。

### 2.4 给 R2 绑公开读域名 → ②

**有自定义域（推荐，正式口径）**：
- 进入桶 → **Settings → Custom Domains → Connect domain**，填一个你已经托管在 Cloudflare 的子域（如 `assets.example.com`），点连接。
- 把 `https://assets.example.com`（**不带末尾斜杠**）记为 ②。

**r2.dev 开发域（B1-3：不建议对外使用）**：
- 官方明确：`r2.dev` 只用于非生产场景，**不支持 WAF、缓存、访问控制、Bot Management**；要用这些能力必须走自定义域。
- 也就是说用 r2.dev 时，第 8 步的 Cache Rules / WAF 限流 / 防盗链**全部配不上**，而 R2 又恰恰没有原生硬性账单上限 —— 这是成本敞口最大的组合。
- 只可用来做一次「文件能不能取到」的连通性检查，检查完立刻 **Settings → Public Development URL → Disable**；正式口径一律用自定义域。

### 2.5 建 R2 S3 API token → S1 / S2
1. R2 概览页右上角 **Manage R2 API tokens → Create API token**。
2. Permission 选 **Object Read & Write**，范围指定到 `trpg-warehouse-assets`。
3. **Create** 后立刻复制 **Access Key ID** → S1、**Secret Access Key** → S2（**只显示一次**，存进密码管理器）。

> 预签名 PUT 走的是 R2 的 S3 端点，这三个值必须齐；只绑 R2 bucket 不够。

## 第 3 步 · Zero Trust 配 Access（只锁写口）

### 3.1 设 team domain → ④
1. 左侧 **Zero Trust**（首次进入选 Free 计划）→ **Settings → Team domain**。
2. 设一个 team name，得到 `xxxx.cloudflareaccess.com`，复制（**不带 `https://`**）→ ④。

### 3.2 建 Self-hosted 应用 → ⑤ + ⑥
1. **Access → Applications → Add an application → Self-hosted**。
2. 应用名随意（如 `trpg-warehouse-upload`），Session Duration 用默认 `24h`。
3. **Application domain / Destinations** 里加**两条**，Domain 都填 ⑥（站点域名）：
   - Path = `/upload*`
   - Path = `/api/upload*`
4. 若部署后发现裸路径 `/upload` 没被拦，再补一条 Path = `/upload`。
5. 策略：**Action = Allow**，**Include = Emails**，填你自己的邮箱；保存。
6. **Zero Trust → Settings → Authentication → Login methods** 里启用 **One-time PIN**（不需要外部身份提供商，邮箱收验证码即可登录）。
7. 回应用 **Overview**，复制 **Application Audience (AUD) Tag** → ⑤。

> ⚠ **不要**用 Worker → Settings → Domains & Routes 里的 **「Enable Cloudflare Access」一键开关**：那个会把整个 Worker 的所有域名（含公开浏览端、预览 URL）全部锁上，与"浏览端公开只读"直接冲突。本项目只锁两条 path。
>
> ⑥ 此时可能还不知道：Workers Builds 部署后才会生成 `https://trpg-warehouse.<你的 workers.dev 子域>.workers.dev`。你可以先填一个预计域名或占位域名——**AUD 是应用 ID，之后改域名不会变**；第 9 步回来校准即可。

## 第 4 步 · GitHub 网页编辑 `wrangler.toml`（一次填 5 个值）

1. 打开 <https://github.com/Luffy852/trpg_warehouse/blob/main/wrangler.toml>。
2. 点右上角**铅笔 Edit**。
3. 只替换注释里标了 `REPLACE_*` 的 5 处（第 6 个值「站点域名」⑥ 不在这里填，用于第 3 步 Access 应用与第 8 步 CORS）：

```toml
database_id             = "① 粘贴 D1 Database ID"
R2_PUBLIC_BASE_URL      = "② https://assets.example.com（自定义域，不带末尾斜杠）"
R2_ACCOUNT_ID           = "③ 粘贴 Account ID"
CF_ACCESS_TEAM_DOMAIN   = "④ xxxx.cloudflareaccess.com"
CF_ACCESS_AUD           = "⑤ 粘贴 AUD Tag"
```

其余保持原样（尤其 `name`、`main`、`[assets].run_worker_first`、两个 `database_name` / `bucket_name`）。

4. 页面底部选 **Commit directly to the main branch**，Commit message 填 `config: 填入 Cloudflare 资源值`，点 **Commit changes**。

> 公开仓库里这几项都不是密钥：Database ID / Account ID / Team domain / AUD 属于资源标识，可以公开。
> **三个真正的密钥（S1/S2/S3）绝不写进仓库**，第 6 步在 Dashboard 里加。

## 第 5 步 · Workers Builds 连 GitHub（真正的"部署"）

1. Cloudflare Dashboard → **Workers & Pages → Create application → GitHub**。
2. 首次会要求授权 Cloudflare 访问 GitHub，按提示点允许；在列表里选 **`Luffy852/trpg_warehouse`**。
3. 配置页这样填：

| 字段 | 填什么 |
|---|---|
| **Project name** | **`trpg-warehouse`**（⚠ 必须和 `wrangler.toml` 里的 `name` 完全一致，否则部署会直接报 "name … must match"） |
| Production branch | `main` |
| **Build command** | **留空**（`web/vendor/*` 已随仓库提交、Worker 的 TS 由 wrangler 自动打包，没有构建步骤） |
| **Deploy command** | 保持默认 `npx wrangler deploy` |
| Root directory | 留空 |

4. 点 **Save and Deploy**，等构建日志全绿（通常几十秒）。

> Workers Builds 会自动 clone 仓库、**自动安装依赖**、再跑 deploy 命令，所以你不需要在本地 `npm install`，也不需要填任何 GitHub Secrets。
> Free 计划每月 3,000 构建分钟、1 个并发、单次 20 分钟超时；**上架模组不触发构建**，只有 push 代码才会，完全够用。
> 部署成功后，Worker 详情页会给出 `https://trpg-warehouse.<子域>.workers.dev`，这就是 ⑥；同时把它填进第 1 步的值清单。

**Workers & Pages → trpg-warehouse → Settings → Variables and Secrets → Add**：

|---|---|---|

## 第 7 步 · D1 建表（网页 SQL 控制台）

**Storage & Databases → D1 → `trpg-warehouse-db` → Explore data / Studio → Query**，粘贴下面整段，点 **Run all statements**：

```sql
CREATE TABLE IF NOT EXISTS modules (
  slug          TEXT PRIMARY KEY,
  title         TEXT NOT NULL,
  system        TEXT NOT NULL,
  kind          TEXT NOT NULL,
  summary       TEXT NOT NULL DEFAULT '',
  cover         TEXT NOT NULL DEFAULT '',
  status        TEXT NOT NULL CHECK (status IN ('draft', 'published')),
  console_file  TEXT NOT NULL,
  mindmap_file  TEXT NOT NULL,
  total_bytes   INTEGER NOT NULL DEFAULT 0,
  created_at    TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at    TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX IF NOT EXISTS idx_modules_status ON modules(status);
CREATE INDEX IF NOT EXISTS idx_modules_system_kind ON modules(system, kind);

CREATE TABLE IF NOT EXISTS upload_locks (
  slug           TEXT PRIMARY KEY,
  reserved_bytes INTEGER NOT NULL,
  updated_at     TEXT NOT NULL DEFAULT (datetime('now'))
);
```

> `total_bytes` 是 **B1-3 成本闸门的累计容量锁**：Worker 在 `finalize` 用 R2 `head().size` 累加每个条目的真实占用，`prepare` 时检查「累计 + 本次 ≤ 8 GB」才放行。
> `upload_locks` 是**预留量表**：浏览器拿到预签名 URL 后关掉页面、`finalize` 失败，R2 里会留下对象但 D1 没有索引 —— 这笔预留量会永久留下，容量锁宁可提前拦死也不少算。**不要给它加定时清理任务**（见 8.8 反模式登记）。
> 少了这两处，上架会分别报 `no such column: total_bytes` 或 `no such table: upload_locks`。
> 若你之前已按旧版指引建过表，在同一个 Query 里补这两段即可：
> ```sql
> ALTER TABLE modules ADD COLUMN total_bytes INTEGER NOT NULL DEFAULT 0;
> CREATE TABLE IF NOT EXISTS upload_locks (
>   slug TEXT PRIMARY KEY, reserved_bytes INTEGER NOT NULL,
>   updated_at TEXT NOT NULL DEFAULT (datetime('now'))
> );
> ```

验证：`SELECT name FROM sqlite_master WHERE type='table';` 应看到 `modules` 与 `upload_locks`；`PRAGMA table_info(modules);` 应看到 `total_bytes`。

## 第 8 步 · R2 CORS + 成本控制（一次性点选）

> **为什么这一整步不能跳过**：R2 Free = **10 GB-month 存储 / 100 万次 Class A（PUT、LIST、multipart）/ 1000 万次 Class B（GET、HEAD）**。Cloudflare 的 **Spend Management 硬支出上限目前只覆盖 Workers 与 Durable Objects，官方明确不含 R2**，所以没有「超了自动停」的总开关。
> 本项目的三层兜底：**8.7 写口闸门（代码已嵌入）+ 8.2/8.3 CDN 缓存与 WAF（这一步点）+ 8.6 账单告警（这一步点）**。四者缺一，费用风险就重新敞口。

### 8.1 CORS（预览 GET + 直传 PUT）

**R2 → `trpg-warehouse-assets` → Settings → CORS Policy → Add CORS policy → JSON tab**，粘贴下面这段（**把 `AllowedOrigins` 换成 ⑥ 站点域名**），点 **Save**：

```json
[
  {
    "AllowedOrigins": ["https://trpg-warehouse.你的子域.workers.dev"],
    "AllowedMethods": ["GET", "HEAD", "PUT"],
    "AllowedHeaders": ["*"],
    "ExposeHeaders": ["ETag", "Content-Length", "Content-Type", "Content-Disposition"],
    "MaxAgeSeconds": 3600
  }
]
```

- `GET` 供思维导图预览页 `fetch` 取 `.xmind`；`PUT` 供浏览器预签名直传；缺一个就分别表现为「预览白屏」或「上传 403」。
- 绑了自定义域的 bucket 会自动返回 CORS 头；若刚改完策略没生效，可在该域名下 **Cache → Purge** 一次。
- 若之后换成自定义站点域名，记得回来把 `AllowedOrigins` 也换成新域名（可保留多条）。

### 8.2 Cache Rules（防 Class B 超量，最有效）

R2 按 **API 操作次数**计费：`GetObject` / `HeadObject` 都是 Class B。边缘缓存命中不再回源 R2，就不产生这次 Class B —— 这是把读取量压下去的主要手段。

1. 进入 **② 自定义域所在的 zone**（不是 Workers & Pages，是域名那一级）→ **Caching → Cache Rules → Create rule**。
2. Rule name 填 `R2 modules cache`。
3. Expression 选 **Custom filter expression / Edit expression**，粘贴（把域名换成你的 ②）：

   ```
   (http.host eq "assets.example.com" and starts_with(http.request.uri.path, "/modules/"))
   ```
4. 设置：
   - **Cache eligibility** → `Eligible for cache`
   - **Edge TTL** → `Ignore cache-control headers and use this TTL`，选 **30 days**（或 7 days）
   - Browser TTL 可留默认
5. **Deploy**。Free 计划允许 10 条 Cache Rules，这一条足够。

> ⚠ **同名文件重新上传后务必清缓存**：同 slug 修订会覆盖 `modules/<slug>/...` 下的同名对象，但边缘仍可能吐旧副本。改完条目到该 zone → **Caching → Configuration → Purge Everything**（或单文件 Purge）。
> 只针对 `/modules/` 路径，**不要**勾选整站 Cache Everything：`/api/*`、`/upload*` 是 Worker 动态路由，缓存它们会破坏列表更新与 Access 校验。
> 预签名 PUT 打的是 `<account>.r2.cloudflarestorage.com`，不是这个域名，缓存规则不影响上传。

### 8.3 WAF 速率限制（防刷，Free 只有 1 条）

1. 同一 zone → **Security → WAF → Rate limiting rules → Create rule**。
2. 表达式：`(http.host eq "assets.example.com")`，**Counting characteristic = IP**。
3. 阈值建议：**10 秒内 20 次**，动作 **Block**，阻断时长 1 小时（可按实际调）。
4. **Deploy**。

> Free 计划每 zone **只允许 1 条** rate limiting rule，所以这一条要覆盖整个 R2 域名，别拆细。它拦的是公开 GET；上传 PUT 在别的 host，不受影响。

### 8.4 Hotlink Protection（可选，防外站盗链）

同一 zone → **Scrape Shield → Hotlink Protection → ON**。主要防图片被别的站点直接嵌入。若要连 HTML / JS / `.xmind` 一起按 Referer 限制，用 WAF 自定义规则补一条（Free 名额有限，非必需）。

> `r2.dev` 开发域**不支持** WAF / 缓存 / 访问控制（官方口径），所以 8.2–8.4 全部只在自定义域下生效 —— 这也是第 2.4 步要求停用 r2.dev 的原因。

### 8.5 Object Lifecycle（只收紧分片，⚠ 不要删对象）

**R2 → bucket → Settings → Object Lifecycle Rules**。

- Cloudflare 的桶**默认已带一条 7 天后终止未完成分片上传**的规则；可在 Dashboard 加一条按前缀 `modules/`、 **1 天** 的 `AbortIncompleteMultipartUpload` 收紧。
- 我们 B1 用的是**预签名单文件 PUT**，本来不走 multipart，这条只是兜底清理残留碎片。
- ⚠ **绝对不要加「N 天后删除对象」/ Expire 规则**：本库是永久公开资料库，加了会把已上架的主控台 / 地图 / `.xmind` 删掉，D1 索引还在但资源 404。第三方那条「自动删除超过指定天数的旧文件」是图床 / 备份场景的建议，对本仓库**不适用**。

### 8.6 Billing 告警 + 定期看用量

- **Billing → Spend Management**：可以把 Workers 的硬支出上限设得极低（如 $0.01）作为「Worker 侧总开关」，但**它不会替 R2 兜底**（官方明确不含 R2、Workers AI、KV 等）；触发时是 Worker 调用被拒（HTTP 1103），静态资源仍可访问、`run_worker_first` 的 `/api/*` 会挂 —— 是可用性熔断，不是 R2 账单熔断。
- **Billing → Notifications**：找账单 / 用量告警项并启用、填接收邮箱；官方 Spend Management 支持阈值邮件通知。若你账户界面里没有 R2 专属告警项，就以 **8.7 容量闸门 + 定期看 R2 → bucket → Metrics** 为准（这一条按界面实际为准，不假设一定存在）。
- 每月扫一眼 **R2 → Metrics** 的 Storage / Class A / Class B 三条曲线，确认离免费额度还远。

### 8.7 写口闸门（已嵌入代码，默认不用点）

B1-3 在 Worker 里加了四道，全部随补丁包进入仓库、**纯点击 Commit 即部署**：

| 闸门 | 默认 | 在哪调 |
|---|---|---|
| 单文件上限 | 50 MB | `wrangler.toml` → `MAX_SINGLE_FILE_MB` |
| 整条目上限 | 200 MB | `MAX_ENTRY_MB` |
| 单次上架文件数 | 500 | `MAX_FILES_PER_ENTRY` |
| **累计容量锁** | **8 GB**（给 10 GB 留 2 GB 余量） | `BUCKET_CAP_GB`（代码钳制 ≤ 10） |

- 上传端把每个文件的 `size` 随 `prepare` 送来；Worker 校验体积 / 数量，并用 D1 的 `modules.total_bytes + upload_locks.reserved_bytes` 算「累计 − 本 slug 旧值 + 本次 ≤ 8 GB」才签预签名 URL。
- `prepare` **先记预留量再签 URL**；`finalize` 索引确认无误后才删预留。上传中途关页面 / 失败会留下永久预留量 —— **宁可提前拦死，也不少算**。
- `finalize` 用 R2 `head().size` 的**真实字节**再复核一次，少报声明会被 `QUOTA_EXCEEDED` 拦下；超容量返回 `BUCKET_CAP_EXCEEDED` 并明确提示去 R2 Dashboard 清理。
- **fail-closed**：D1 查询失败、令牌缺成本字段、`head().size` 不可用、配置值不可信 → 一律 `503` / `413` 拒绝，绝不「算了放行」。
- 列表接口只查 D1、**从不执行 `ListObjects`**（Class A 里较贵的操作），这一条架构上天然满足。

### 8.8 一键熔断（纯点击）+ 反模式登记 ★

**先看这一条**：用户已明确「这种免费页面工具，宁愿在代码设计不够好的时候崩掉或者停止访问，也比为此支付一个大账单要好」。所以本项目提供**两个纯点击、立刻生效**的停机开关，不引入任何常驻脚本：

| 想停什么 | 网页里点哪里 | 生效 |
|---|---|---|
| **停止写 R2 / 写 D1**（Class A、存储增长） | GitHub 网页编辑 `wrangler.toml`，把 `WRITES_ENABLED = "1"` 改成 `"0"` → Commit | Workers Builds 自动部署后，`prepare` / `finalize` 一律 503 `WRITES_DISABLED` |
| **停止公开读**（Class B） | R2 → bucket → **Settings → Custom Domains → 该域名 → … → Disable domain** | 立刻，公开 GET 断掉；主页 / 条目页静态壳仍在，但资源取不到 |

恢复：把 `WRITES_ENABLED` 改回 `"1"`、重新 Enable domain 即可，无需改代码、无需重建。**发现用量异常先拉这两个闸，再去查原因。**

**反模式登记（来自历史教训：一个定时遍历 alarm 一天烧爆 Durable Objects 免费读写次数）**

> 那个设计的理论收益是「随时掌握最新状态」，实跑成本是「定时器 × 遍历全部对象 × 每天」，收益成本完全不对等。本轮对所有成本机制做了同样的核算，**明确禁止**以下写法：

| 禁止 | 为什么 | 本项目替代 |
|---|---|---|
| `scheduled` / Cron Trigger / DO alarm / `setInterval` 定时查用量 | 定时 × 遍历 = 额度杀手，且 R2 没有原生 GraphQL 用量数据集可直接查 | 容量核算只在 `prepare` / `finalize` 两次**写口**做，由 Access 保护 + 人触发 |
| 每次请求都去查 R2 用量 / `list()` 全桶 | 把成本检查放到高频读路径，检查本身就产生 Class A/B | D1 单行 `SUM` 聚合（`modules` + `upload_locks`），O(条目数)、低频 |
| 为「拿到精确值」而遍历桶做对账 | 精确 ≠ 值得；`ListObjects` 是较贵的 Class A | 用 `total_bytes` 账面值 + 预留量，允许高估、绝不允许低估 |
| 自动熔断脚本（GraphQL 查用量 → 调 API 删 token / 停域名） | 需常驻 Cron + API Token + 脚本托管，与纯点击口径冲突；且**删 API Token 对公开自定义域的 GET 无效** | 8.8 两个手动开关 + 8.6 告警 |

**成本机制自身的用量账（写口一次上架，最坏情况）**：

| 操作 | 次数 | 计费归类 |
|---|---|---|
| D1 读（容量聚合 + 写后读回） | 2 | D1 读行数，免费 500 万行/天 |
| D1 写（预留 + 索引 + 删预留） | 3 | D1 写行数，免费 10 万行/天 |
| R2 `head()`（finalize 复核） | ≤ 500（= 单次上架文件数上限） | Class B，免费 1000 万次/月 |
| R2 `list()` / GraphQL / 定时调用 | **0** | — |
| 浏览端请求触发的成本核算 | **0** | — |

> 也就是说：**不上架就不产生任何成本核算开销**。这与「每天定时跑一遍」的设计有本质区别。沙盒另加了一条静态断言，扫描 `worker/src` / `shared` / `web/assets` / `scripts` 里出现 `setInterval` / `scheduled` / `cron` / `alarm` / `GraphQL` / `.list(` 即判红，防止后续改动把反模式带回来。

### 这一套能锁到什么程度（不夸大）

**仍然不是「自动硬熔断」，但已经可以一键停机。** 8.2/8.3 把「缓存未命中的 Class B」压低，8.7 把存储量锁在 8 GB 以内且 fail-closed，8.6 提供告警，8.8 提供两个纯点击开关；但恶意刷自定义域且不断制造缓存未命中，理论上仍会累积 Class B。官方没有 R2 硬性账单上限，所以**不能承诺 100% 零费用、也不能承诺「无需人工干预」**。

按你的偏好，这里明确取舍：**不做自动熔断脚本**（常驻 Cron + API Token 会引入新的成本与复杂度，且历史上「定时遍历」正是把免费额度烧爆的模式），改为「机制本身零高频开销 + 账面宁可高估 + 异常时一键停机」。真要 100% 自动，只能等官方把 R2 纳入 Spend Management。

## 之后怎么改代码 / 重新部署

依然纯点击：在 **GitHub 网页编辑文件 → Commit changes**，Workers Builds 会自动重新构建并部署，无需再来一遍第 2–9 步。

- 改了 `web/assets/*.js`（前端源码）→ 需要重新生成 `web/vendor/*`。这一步目前需要构建工具，属于**改代码**而不是**部署**；如果你希望连这也纯点击，下一轮可以把它改成"在网页里编辑 `web/vendor/*` 生成物"或加一个 GitHub Actions 自动构建。
- 改了 `worker/src/*.ts`、`shared/*.js`、`wrangler.toml`、`package.json` → 直接 Commit 即可自动部署。
- **上架模组不会触发构建**：资源进 R2、索引进 D1，站点即时可见。
