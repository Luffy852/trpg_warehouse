## 本版固定的两个「门牌」

用大白话先记住：你的域名 `finewinginnovation.cn` 是一条街，这次要在这条街上挂**两块不同的门牌**。

| | 前台（站点） | 文件仓库（R2） |
|---|---|---|
| 门牌 | **`warehouse.finewinginnovation.cn`** | **`warehouseasset.finewinginnovation.cn`** |
| 放什么 | 首页、分类卡片、条目页、上传页这些「页面」 | 主控台 HTML、地图图片、`.xmind` 思维导图这些「大件文件」 |
| 谁去 | 访客进来逛；你登录后上传 | 浏览器按页面上的链接，直接来把文件取出来显示 |
| 文档里的编号 | **⑥ 站点域名** | **② R2 公开读基址** |
| 填到哪 | 登录保护的应用域名、CORS 允许名单 | `wrangler.toml` 的 `R2_PUBLIC_BASE_URL`、缓存规则 |

**两者怎么关联**：访客在前台点「思维导图」，页面会按 ② 的门牌去仓库取 `.xmind`；反过来，仓库门口的 CORS 设置里要写上 ⑥ 的门牌 —— 大白话就是「仓库只认从前台来的浏览器请求」。两块门牌同属一条街，DNS 都在 Cloudflare 的 `finewinginnovation.cn` 这个 zone 里管，不用新建 zone。

> 为什么 ② 用 `warehouseasset.`（一个点）而不是 `warehouse.asset.`（两个点），以及「能不能锁得住」，见**附录 B**；如果你坚持用两个点的写法，替换清单见**附录 C**。

## 本版相对旧指引改了什么

1. **⑥ 从「先不知道、第 9 步回来校准」改成「一开始就定为 `warehouse.finewinginnovation.cn`」**：第 3 步直接填，不用占位域名。

## 本修订版按真机实测校准了什么（2026-11-20）

## 第 2 步 · Cloudflare Dashboard 建资源

### 2.1 复制 Account ID → ③
登录 <https://dash.cloudflare.com>，在账户首页 / 右侧栏找到 **Account ID**，复制。

### 2.2 建 D1 数据库 → ①
1. 左侧 **Storage & Databases → D1 SQL Databases → Create database**。
2. 数据库名填 **`trpg-warehouse-db`**（必须和 `wrangler.toml` 里的 `database_name` 完全一致），选位置后 **Create**。
3. 进入详情页，复制 **Database ID** → ①。

> 先不要建表，建表在第 7 步（同样在网页里粘贴 SQL）。

### 2.3 建 R2 桶 → ② 的「柜子」
1. 左侧 **R2 Object Storage → Create bucket**。
2. 桶名填 **`trpg-warehouse-assets`**（必须和 `wrangler.toml` 里的 `bucket_name` 完全一致），**Create bucket**。

### 2.4 给 R2 绑公开读域名 → ②

1. 进入桶 → **Settings → Custom Domains → Add / Connect domain**。
2. 填 **`warehouseasset.finewinginnovation.cn`** → **Continue** → 核对即将自动添加的 DNS 记录 → **Connect Domain**。
3. 状态会从 `Initializing` 变成 `Active`，**等几分钟并刷新**；若一直不变，点该域名旁的 `…` → **Retry connection**。
4. 把 `https://warehouseasset.finewinginnovation.cn`（**不带末尾斜杠**）记为 ②。

> **这一步连完之后，这块门牌就是「公开可读」的** —— 这是本项目**故意要的**，不是配置失误：访客浏览器要按页面上的链接来取 `.xmind`、主控台 HTML、地图图片。为什么不能把它锁死、以及能锁到什么程度，见**附录 B 第 2 问**。
> **本版不启用 `r2.dev` 开发域**。官方明确：想用 WAF、缓存、访问控制、Bot Management，就必须走自定义域；`r2.dev` 只用于非生产场景，这些能力一概没有。桶默认也不公开，别去开 Public Development URL。

### 2.5 建 R2 S3 API token → S1 / S2
1. R2 概览页右上角 **Manage R2 API tokens → Create API token**。
2. Permission 选 **Object Read & Write**，范围指定到 `trpg-warehouse-assets`。
3. **Create** 后立刻复制 **Access Key ID** → S1、**Secret Access Key** → S2（**只显示一次**，存进密码管理器）。

> 预签名 PUT 走的是 R2 的 S3 端点，这三个值必须齐；只绑 R2 bucket 不够。

### 2.6 顺手确认
回桶 → **Settings**：`r2.dev` / Public Development URL 保持 **Disabled**；Custom Domains 里只有 `warehouseasset.finewinginnovation.cn` 一条且为 Active。

## 第 3 步 · Zero Trust 配 Access（只锁写口）

> **本步按 2026-11 现行界面写**。旧指引里的 `Settings → Authentication → Login methods` 页面已经不存在；若你在别处看到那种写法，是过期资料。

### 3.1 确认 team domain → ④
1. 左侧 **Zero Trust**（首次进入选 Free 计划）→ **Settings → Team domain**。
2. 这一页 `Full domain` 形如 `xxxx.cloudflareaccess.com`，复制（**不带 `https://`**）→ ④。
3. **本窗口已定值**：`finewinginnovation.cloudflareaccess.com`。若你是重做一遍，按自己页面上的值填。

> 新版 `Settings` 页右侧 `ON THIS PAGE` 只有 **Team domain / Downloads / Admin controls / Plan / Permissions** —— 没有 `Authentication`，登录方式不在这里配（见 3.2-A）。

### 3.2-A 先加「邮箱验证码」登录方式（新版必做，旧版没有这步）
**`Zero Trust → Integrations → Identity providers`** → 在 `Your identity providers` 卡片点 **`Add new identity provider`** → 选 **One-time PIN** → **Save**。不用填任何配置。

- 大白话：这一步决定「用什么办法证明你是你」。**2026-06-18 起，新建的 Zero Trust 组织默认只给「用 Cloudflare 账号登录」，邮箱验证码不再自动送**；不手动加，登录页就不会出现「输入邮箱 → 发验证码」。
- 加完登录页会同时显示 `Cloudflare` 与 `Email / Send login code` 两项，属正常；PIN 10 分钟有效、用一次作废，且只发给被 Allow 策略允许的邮箱。
- 企业邮箱若收不到码，让邮件网关放行 `noreply@notify.cloudflare.com` / `notify.cloudflare.com`。

### 3.2-B 建 Self-hosted 应用 → ⑤
1. **`Zero Trust → Access controls → Applications`** → **Add an application**（或 `Create new application`）→ **Self-hosted**（新版可能显示 `Self-hosted and private`）。
2. 应用名随意（如 `trpg-warehouse-upload`），Session Duration 用默认 `24h`。
3. **Destinations / 公开主机名** 加**两条**，都指向 ⑥ `warehouse.finewinginnovation.cn`：
   - Path = `/upload*`
   - Path = `/api/upload*`
   - 新版界面可能把域名**拆成几栏**（子域格填 `warehouse`、域下拉选 `finewinginnovation.cn`、路径格填 `/upload*`）；按界面实际给的格子照填即可，两种写法指向同一块门牌。
4. 策略：**Action = Allow**，**Include = Emails**，填你自己的邮箱 → **Save / Create**。
5. 若部署后发现裸路径 `/upload` 没被拦，再补一条 Path = `/upload`。
6. **保存完应用** → 回到 `Access controls → Applications` → 选中该应用 → **Edit → Additional settings** → 复制 **`Application Audience (AUD) Tag`** → ⑤。

> **AUD 一定在保存之后才有**：创建向导里看不到；也不要去全局 `Settings` 或应用 `Overview` 找（旧版位置已换）。

### 三条红线（都在这几个页面上，顺手记牢）

## 第 7 步 · D1 建表（网页 SQL 控制台）

> ⚠ **这一步排在「第 5 步部署成功」之后，别提前跳过**。漏做的表现很固定：首页能打开但显示「载入失败：列表接口返回 500」，直接开 `/api/modules` 则是 **Error 1101 / Worker threw exception** —— 那是同一件事（Worker 查 `modules` 表，表还不存在），不是代码坏了、也不是 Secret 没加。建完表刷新即可。

**Storage & Databases → D1 → `trpg-warehouse-db` → Explore data / Studio → Query**，粘贴下面整段，点 **Run all statements**：

```sql
CREATE TABLE IF NOT EXISTS modules (
  slug          TEXT PRIMARY KEY,
  title         TEXT NOT NULL,
  system        TEXT NOT NULL,
  kind          TEXT NOT NULL,
  summary       TEXT NOT NULL DEFAULT '',
  cover         TEXT NOT NULL DEFAULT '',
  status        TEXT NOT NULL CHECK (status IN ('draft', 'published')),
  console_file  TEXT NOT NULL,
  mindmap_file  TEXT NOT NULL,
  total_bytes   INTEGER NOT NULL DEFAULT 0,
  created_at    TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at    TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX IF NOT EXISTS idx_modules_status ON modules(status);
CREATE INDEX IF NOT EXISTS idx_modules_system_kind ON modules(system, kind);

CREATE TABLE IF NOT EXISTS upload_locks (
  slug           TEXT PRIMARY KEY,
  reserved_bytes INTEGER NOT NULL,
  updated_at     TEXT NOT NULL DEFAULT (datetime('now'))
);
```

> `total_bytes` 是成本闸门的累计容量锁：Worker 在 `finalize` 用 R2 `head().size` 累加每个条目的真实占用，`prepare` 时检查「累计 + 本次 ≤ 5 GB」才放行。
> ★ 这个 R2 可能与另一个项目共用：5 GB 是本项目 `modules/` 这部分的**自限额**，不是云端硬隔离；R2 Free 的 10 GB-month 按整个桶算，两边合起来是否超额要各自守住。校准与「仓库规模」也只统计 `modules/` 前缀。
> `upload_locks` 是预留量表：浏览器拿到预签名 URL 后关掉页面、`finalize` 失败，R2 里会留下对象但 D1 没有索引 —— 这笔预留量会永久留下，容量锁宁可提前拦死也不少算。**不要给它加定时清理任务**（见 8.8 反模式登记）。
> 少了这两处，上架会分别报 `no such column: total_bytes` 或 `no such table: upload_locks`。
> 若之前已按旧版指引建过表，在同一个 Query 里补这两段即可：
> ```sql
> ALTER TABLE modules ADD COLUMN total_bytes INTEGER NOT NULL DEFAULT 0;
> CREATE TABLE IF NOT EXISTS upload_locks (
>   slug TEXT PRIMARY KEY, reserved_bytes INTEGER NOT NULL,
>   updated_at TEXT NOT NULL DEFAULT (datetime('now'))
> );
> ```

验证：`SELECT name FROM sqlite_master WHERE type='table';` 应看到 `modules` 与 `upload_locks`；`PRAGMA table_info(modules);` 应看到 `total_bytes`。

## 第 8 步 · R2 CORS + 成本控制（一次性点选）

> **为什么这一整步不能跳过**：R2 Free = **10 GB-month 存储 / 100 万次 Class A（PUT、LIST、multipart）/ 1000 万次 Class B（GET、HEAD）**。Cloudflare 的 **Spend Management 硬支出上限目前只覆盖 Workers 与 Durable Objects，官方明确不含 R2**，所以没有「超了自动停」的总开关。
> 本项目的三层兜底：**8.7 写口闸门（代码已嵌入）+ 8.2/8.3 CDN 缓存与 WAF（这一步点）+ 8.6 账单告警（这一步点）**。四者缺一，费用风险就重新敞口。
> **本步所有「zone 级」配置都在 `finewinginnovation.cn` 这一个 zone 里做**，不要新建 zone。

### 8.1 CORS（预览 GET + 直传 PUT）

**R2 → `trpg-warehouse-assets` → Settings → CORS Policy → Add CORS policy → JSON tab**，粘贴下面这段，点 **Save**：

```json
[
  {
    "AllowedOrigins": ["https://warehouse.finewinginnovation.cn"],
    "AllowedMethods": ["GET", "HEAD", "PUT"],
    "AllowedHeaders": ["*"],
    "ExposeHeaders": ["ETag", "Content-Length", "Content-Type", "Content-Disposition"],
    "MaxAgeSeconds": 3600
  }
]
```

- `GET` 供思维导图预览页 `fetch` 取 `.xmind`；`PUT` 供浏览器预签名直传；缺一个就分别表现为「预览白屏」或「上传 403」。
- 绑了自定义域的 bucket 会自动返回 CORS 头；若刚改完策略没生效，可在该域名下 **Cache → Purge** 一次。
- ⚠ `AllowedOrigins` 填的是 **⑥ 前台门牌**，不是 ② 仓库门牌。CORS 只约束「浏览器里的跨站脚本」，**不等于访问控制**（见附录 B 第 2 问）。

### 8.2 Cache Rules（防 Class B 超量，最有效）

R2 按「API 操作次数」计费：`GetObject` / `HeadObject` 都是 Class B。边缘缓存命中不再回源 R2，就不产生这次 Class B —— 这是把读取量压下去的主要手段。

1. 进入 **`finewinginnovation.cn` 这个 zone**（不是 Workers & Pages，是域名那一级）→ **Caching → Cache Rules → Create rule**。**2026-11-23 真机复核：路径未变**（`Caching` 展开为 `Overview / Configuration / Cache Rules / Tiered Cache / Cache Reserve / Workers Routes / Rules`）。
2. Rule name 填 `R2 modules cache`。
3. Expression 选 **Custom filter expression / Edit expression**，粘贴：

   ```
   (http.host eq "warehouseasset.finewinginnovation.cn" and starts_with(http.request.uri.path, "/modules/"))
   ```
4. 设置：
   - **Cache eligibility** → `Eligible for cache`
   - **Edge TTL** → `Ignore cache-control headers and use this TTL`，选 **30 days**（或 7 days）
   - Browser TTL 可留默认
5. **Deploy**。Free 计划允许 10 条 Cache Rules，这一条足够。

> ⚠ **同名文件重新上传后务必清缓存**：同 slug 修订会覆盖 `modules/<slug>/...` 下的同名对象，但边缘仍可能吐旧副本。改完条目到该 zone → **Caching → Configuration → Purge Everything**（或单文件 Purge）。
> 只针对 `/modules/` 路径，**不要**勾选整站 Cache Everything：`/api/*`、`/upload*` 是 Worker 动态路由，缓存它们会破坏列表更新与登录校验。
> 预签名 PUT 打的是 `<account>.r2.cloudflarestorage.com`，不是这个域名，缓存规则不影响上传。

### 8.3 WAF 速率限制（防刷，Free 只有 1 条）

1. 同一 zone → **`Security → Security rules → Rate limiting rules → Create rule`**。⚠ **2026-11-23 界面改名校正**：旧版写 `Security → WAF → Rate limiting rules`，**WAF 字样已消失**；当前页面按 `Custom rules / Rate limiting rules / Managed rules / Zone lockdown rules` 分区块，顶部另有 `DoS protection` 标签页。规则只认「Rate limiting rules 区块里有一条 Active / Block」，不认旧菜单名。
2. 表达式：`(http.host eq "warehouseasset.finewinginnovation.cn")`，**Counting characteristic = IP**。
3. 阈值建议：**10 秒内 20 次**，动作 **Block**。
4. **阻断时长按界面实际给的上限填**：本窗口在 Free 档真机实测**只能选 10 秒、没有 1 小时选项**，按「10 秒 20 次 / 阻断 10 秒」设置即可。**第 10 步 #14 只检查「有没有这条规则」，不查阻断多久**；成本控制主力是 8.2 缓存与 8.7 写口容量锁，不必为时长升级付费。
5. **Deploy**。

> Free 计划每 zone **只允许 1 条** rate limiting rule，所以这一条要覆盖整个 ② 域名，别拆细。它拦的是公开 GET；上传 PUT 在别的 host，不受影响。

### 8.4 Hotlink Protection（**可选 · 跳过不影响验收**）

新版 zone 侧栏里**已经没有 `Scrape Shield` 这一项**（现行侧栏是 Overview / AI Crawl Control / Agent Readiness / Analytics / DNS / Email / SSL/TLS / Security / Access / Speed / Caching / Workers Routes / Rules / Error Pages / Network / Traffic / Web3）。

现行位置：**同一 zone → `Security → Settings` → 找到 `Hotlink Protection` → 开关拨到 On**。

- 大白话：它只防「别的网站把你的图片直接嵌过去用、白耗你带宽」，**只管图片**，`.xmind` / HTML 不归它管。
- 本步原本就是**可选**，第 10 步 #14 不检查它。找不到就跳过，**不要为了凑步骤去翻菜单**；8.1 的 CORS 才是必须项。
- 若要连 HTML / JS / `.xmind` 一起按 Referer 限制，用 WAF 自定义规则补一条（Free 名额有限，非必需）。

### 8.5 Object Lifecycle（**默认就是标准答案，什么都不用点**）

**R2 → bucket → Settings → Object Lifecycle Rules**。本窗口真机实测的默认状态如下，逐项读一遍即可：

| 图上内容 | 判定 |
|---|---|
| `Object lifecycle rule is enabled` = 开 | 生效中 ✓ |
| Rule name = `Default Multipart Abort Rule` | 桶自带的分片清理规则 ✓ |
| Rule scope / 前缀 = 空 | 整桶适用 ✓ |
| ✅ 只勾 `Abort incomplete multipart uploads after: 7 Days` | 只清「传了一半断掉的碎片」 ✓ |
| ⬜ `Delete uploaded objects after` **没勾** | **关键**：不会删已上架文件 ✓ |
| ⬜ `Transition objects to Infrequent Access` **没勾** | 不会动文件 ✓ |

- 本项目用**预签名单文件 PUT**，本来不走 multipart，这条默认规则几乎用不上；旧指引建议的「按前缀 `modules/` 收紧到 1 天」只是**可选优化，不必做**。
- ⚠ **绝对不要勾「N 天后删除对象」/ Expire 规则**：本库是永久公开资料库，勾了会把已上架的主控台 / 地图 / `.xmind` 删掉，D1 索引还在但资源 404。
- 一句话：**没看懂所以没动，恰好是最正确的操作**。不要为了「完成步骤」去点出危险规则。

### 8.6 Billing 告警 + 定期看用量

- **Billing → Spend Management**：可以把 Workers 的硬支出上限设得极低（如 $0.01）作为「Worker 侧总开关」，但**它不会替 R2 兜底**（官方明确不含 R2）；触发时是 Worker 调用被拒（HTTP 1103），静态资源仍可访问、`run_worker_first` 的 `/api/*` 会挂 —— 是可用性熔断，不是 R2 账单熔断。
- **Billing → Notifications**：找账单 / 用量告警项并启用、填接收邮箱。若你账户界面里没有 R2 专属告警项，就以 **8.7 容量闸门 + 定期看 R2 → bucket → Metrics** 为准（这一条按界面实际为准，不假设一定存在）。
- 每月扫一眼 **R2 → Metrics** 的 Storage / Class A / Class B 三条曲线，确认离免费额度还远。

### 8.7 写口闸门（已嵌入代码，默认不用点）

| 闸门 | 默认 | 在哪调 |
|---|---|---|
| 单文件上限 | 50 MB | `wrangler.toml` → `MAX_SINGLE_FILE_MB` |
| 整条目上限 | 200 MB | `MAX_ENTRY_MB` |
| 单次上架文件数 | 500 | `MAX_FILES_PER_ENTRY` |
| **累计容量锁（本项目 `modules/` 部分）** | **5 GB**（共用桶给另一项目留额度） | `BUCKET_CAP_GB`（代码钳制 ≤ 10） |

- 上传端把每个文件的 `size` 随 `prepare` 送来；Worker 校验体积 / 数量，并用 D1 的 `modules.total_bytes + upload_locks.reserved_bytes` 算「累计 − 本 slug 旧值 + 本次 ≤ 5 GB」才签预签名 URL（只算本项目 `modules/` 的账，不含共用桶里另一项目的对象）。
- `prepare` **先记预留量再签 URL**；`finalize` 索引确认无误后才删预留。上传中途关页面 / 失败会留下永久预留量 —— 宁可提前拦死，也不少算。
- `finalize` 用 R2 `head().size` 的**真实字节**再复核一次，少报声明会被 `QUOTA_EXCEEDED` 拦下；超容量返回 `BUCKET_CAP_EXCEEDED` 并明确提示去 R2 Dashboard 清理。
- **fail-closed**：D1 查询失败、令牌缺成本字段、`head().size` 不可用、配置值不可信 → 一律 `503` / `413` 拒绝，绝不「算了放行」。
- 列表接口只查 D1、**从不执行 `ListObjects`**，这一条架构上天然满足。

### 8.8 一键熔断（纯点击）+ 反模式登记 ★

**先看这一条**：你已明确「这种免费页面工具，宁愿在代码设计不够好的时候崩掉或者停止访问，也比为此支付一个大账单要好」。所以本项目提供两个纯点击、立刻生效的停机开关，不引入任何常驻脚本：

| 想停什么 | 网页里点哪里 | 生效 |
|---|---|---|
| **停止写 R2 / 写 D1**（Class A、存储增长） | GitHub 网页编辑 `wrangler.toml`，把 `WRITES_ENABLED = "1"` 改成 `"0"` → Commit | Workers Builds 自动部署后，`prepare` / `finalize` 一律 503 `WRITES_DISABLED` |
| **停止公开读**（Class B） | R2 → bucket → **Settings → Custom Domains → `warehouseasset.finewinginnovation.cn` → … → Disable domain** | 立刻，公开 GET 断掉；前台页面还在，但资源取不到 |

恢复：把 `WRITES_ENABLED` 改回 `"1"`、重新 Enable domain 即可，无需改代码、无需重建。**发现用量异常先拉这两个闸，再去查原因。**

**反模式登记（来自历史教训：一个定时遍历 alarm 一天烧爆 Durable Objects 免费读写次数）**

> 那个设计的理论收益是「随时掌握最新状态」，实跑成本是「定时器 × 遍历全部对象 × 每天」，收益成本完全不对等。明确禁止以下写法：

| 禁止 | 为什么 | 本项目替代 |
|---|---|---|
| `scheduled` / Cron Trigger / DO alarm / `setInterval` 定时查用量 | 定时 × 遍历 = 额度杀手 | 容量核算只在 `prepare` / `finalize` 两次**写口**做，由登录保护 + 人触发 |
| 每次请求都去查 R2 用量 / `list()` 全桶 | 把成本检查放到高频读路径，检查本身就产生 Class A/B | D1 单行 `SUM` 聚合，O(条目数)、低频 |
| 为「拿到精确值」而遍历桶做对账 | 精确 ≠ 值得；`ListObjects` 是较贵的 Class A | 用 `total_bytes` 账面值 + 预留量，允许高估、绝不允许低估 |
| 自动熔断脚本（GraphQL 查用量 → 调 API 删 token / 停域名） | 需常驻 Cron + API Token + 脚本托管，与纯点击口径冲突；且**删 API Token 对公开自定义域的 GET 无效** | 8.8 两个手动开关 + 8.6 告警 |

**成本机制自身的用量账（写口一次上架，最坏情况）**：

| 操作 | 次数 | 计费归类 |
|---|---|---|
| D1 读（容量聚合 + 写后读回） | 2 | D1 读行数，免费 500 万行/天 |
| D1 写（预留 + 索引 + 删预留） | 3 | D1 写行数，免费 10 万行/天 |
| R2 `head()`（finalize 复核） | ≤ 500 | Class B，免费 1000 万次/月 |
| R2 `list()` / GraphQL / 定时调用 | **0** | — |
| 浏览端请求触发的成本核算 | **0** | — |

> **不上架就不产生任何成本核算开销**。沙盒另加了一条静态断言，扫描源码里出现 `setInterval` / `scheduled` / `cron` / `alarm` / `GraphQL` / `.list(` 即判红，防止后续改动把反模式带回来。

### 这一套能锁到什么程度（不夸大）

**仍然不是「自动硬熔断」，但已经可以一键停机。** 8.2/8.3 把「缓存未命中的 Class B」压低，8.7 把本项目用量锁在 5 GB 以内且 fail-closed，8.6 提供告警，8.8 提供两个纯点击开关；但恶意刷自定义域且不断制造缓存未命中，理论上仍会累积 Class B。官方没有 R2 硬性账单上限，所以**不能承诺 100% 零费用、也不能承诺「无需人工干预」**。按你的偏好，这里明确取舍：**不做自动熔断脚本**，改为「机制本身零高频开销 + 账面宁可高估 + 异常时一键停机」。

## 附录 B · 门牌与公开性（三问三答，给非技术读者）

### 1）点太多是不是不行？`warehouse.asset.` 合法吗？

**DNS 上完全合法**。域名像楼层号，`warehouse.asset.finewinginnovation.cn` 只是多分了一层，互联网规则里没有「最多两个点」的限制。

问题不在「点数」，而在**免费 HTTPS 证书只认一层**。简单科普：浏览器访问 `https://` 时，服务器要出示一张「身份证」。Cloudflare 免费送的那张是**通配身份证**，写的是「本街所有一层门牌」（`*.finewinginnovation.cn`），像 `warehouse.finewinginnovation.cn`、`warehouseasset.finewinginnovation.cn` 都在名单上；但 `warehouse.asset.finewinginnovation.cn` 是**两层门牌**，不在这张名单里，浏览器就会报「连接不安全」。要覆盖它得买付费的高级证书或开 Total TLS —— 为一个文件仓库门牌花这个钱不划算。

R2 那侧还有一层特殊：官方说 R2 自定义域用的是「按每个具体门牌单独签发」的证书，理论上可能不受上面那条限制；但**官方公开文档没有明说多级子域一定能在 R2 上激活**，状态有可能一直卡在 `Initializing`。首次部署不值得赌这个。

**所以本版建议：`warehouseasset.finewinginnovation.cn`（一个点）**，它是你自己提的备选，读起来也清楚（warehouse + asset），落在免费证书覆盖内，零额外成本、零不确定。⑥ 前台 `warehouse.finewinginnovation.cn` 本来就是一层，没问题。

### 2）这块门牌会变成外部可访问的吗？能不能锁得住？

**会，而且是故意的**。Cloudflare 的桶默认从不公开，必须你显式点「Connect domain」才打开；本版第 2.4 步点了，所以 `warehouseasset.finewinginnovation.cn` 就是全网可读的。这不是漏洞，是站点功能本身：访客浏览器要按页面上的链接来取 `.xmind`、主控台 HTML、地图图片。项目档案里定的口径本来就是「**资源文件仍公开可读，入口只在主控台里**」—— 我们不列清单、不推送，但也不假装它是秘密。

**「能不能锁得住」分三层说**：

| 想达到什么 | 能不能 | 怎么做 / 代价 |
|---|---|---|
| 让全网都打不开这块门牌 | **能，但站点会一起坏** | R2 → Settings → Custom Domains → **Disable domain**（8.8 一键熔断）。公开 GET 立刻断；代价是思维导图预览、主控台内链全部 404。**这正是紧急停机用的闸**，不是日常状态 |
| 限制「只有从前台来的浏览器请求能取」 | **能，但别误以为这是锁** | 8.1 的 CORS `AllowedOrigins` 只写 ⑥。它约束的是「浏览器里的跨站脚本」——**把资源 URL 直接贴进地址栏照样能打开**。防盗用可以，当保险箱不行 |
| 防止被刷 / 被外站盗链 | **能，压到很低** | 8.2 缓存（同一文件不重复回源）、8.3 WAF 限流（同一 IP 短时间太多次就拦；Free 档上限 10 秒）、8.4 防盗链（可选）、8.7 写口 5 GB 容量锁 |

一句话：**能「一键关掉」，不能「既锁死又让站点正常」**。`warehouseasset`（无点）和 `warehouse.asset`（多点）在这件事上**完全一样**，点数不影响权限。

### 3）那两块门牌分别填在哪，别填串了

| 填在哪 | 该填谁 |
|---|---|
| `wrangler.toml` 的 `R2_PUBLIC_BASE_URL`（②） | `https://warehouseasset.finewinginnovation.cn` |
| `wrangler.toml` 末尾 `[[routes]]` 的 `pattern` | `warehouse.finewinginnovation.cn` |
| Zero Trust 登录保护应用的 Domain（⑥） | `warehouse.finewinginnovation.cn` |
| R2 CORS 的 `AllowedOrigins` | `https://warehouse.finewinginnovation.cn` |
| 8.2 Cache Rule / 8.3 WAF 表达式里的 `http.host` | `warehouseasset.finewinginnovation.cn` |
| 第 10 步验收用的资源 URL 前缀 | `https://warehouseasset.finewinginnovation.cn/modules/...` |

> 最常见的填串：把 ② 当成 CORS 允许名单填进去 → 表现为「思维导图白屏 / 上传 403」；把 ⑥ 当成缓存规则域名 → 缓存规则不生效，`cf-cache-status` 一直不是 HIT。

## 附录 C · 若你仍坚持用 `warehouse.asset.finewinginnovation.cn`

DNS 上没问题，但请先接受两点：**① 免费通配证书不覆盖两层门牌，浏览器可能报不安全；② 官方未明确承诺 R2 自定义域的多级子域一定能激活，状态可能卡 `Initializing`**。若你愿意先试，需要同步替换下面 **5 处**（少改一处就会出现「首页正常但导图白屏」这类半通不通的状态）：

1. 第 2.4 步 Connect domain 填 `warehouse.asset.finewinginnovation.cn`；等状态变 Active，并**用浏览器直接打开该地址确认没有证书警告**。
2. 第 4 步 `R2_PUBLIC_BASE_URL` = `https://warehouse.asset.finewinginnovation.cn`。
3. 第 8.2 / 8.3 表达式里的 `http.host eq "warehouseasset.finewinginnovation.cn"` → 改成 `"warehouse.asset.finewinginnovation.cn"`。
4. 第 10 步第 13 项的资源 URL 前缀改成 `https://warehouse.asset.finewinginnovation.cn/modules/...`。
5. 排错表与附录 B 第 3 问里的对应字符串一并替换（文档留档用）。

若卡在证书或 `Initializing`，**最省事的退路就是换回一级子域 `warehouseasset.finewinginnovation.cn`**，按上面 5 处反向改回来即可，不改任何代码。
