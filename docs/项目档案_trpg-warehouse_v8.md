| 口径 | 结论 |
|---|---|
| 项目性质 | 内容库 / 线上站点；**≠** 本地 `ttrpg-module-prep`（生产工具 / 模板库），后者留在本地不改造 |

### 0.5 禁改清单（源码注释里写了原因，这里再提一次）

- **`web/vendor/*` 不许直接改**：是 `web/assets/*.js` 经 esbuild 生成的产物，改了源码跑 `npm run build` 重出（手册 6.3「改脚本不改产物」；直接改产物会在下次构建被覆盖）。
- **`shared/*.js` 不许各端各写一份**：枚举 / slug / 剥顶层 / 依赖解析 / xmind 格式判定是 Worker、上传端、预览页、测试的**唯一口径出处**，改口径只改这一处（原则 6 派生值不存副本 / 原则 7）。
- **不许在 Worker 里解 `.xmind`、不许上传端导出 HTML/SVG 副本**：解析只发生在访客浏览器，`.xmind` 原文件是唯一真值（A-1d；Worker 3 MB / 10 ms CPU 限额）。
- **不许把 D1 / R2 绑定和 vars 只加在 Cloudflare Dashboard**：Workers Builds 每次 Git 部署以 `wrangler.toml` 覆写，Dashboard 手加的会静默消失（B1-2 核实）。真实值必须写回仓库；3 个 Secret 例外。
- **不许用 Worker 的「Enable Cloudflare Access」一键开关**：它会锁住整个站点而非只锁写口，与「浏览端公开只读」冲突。
- **不许在部署指引里重新引入本地 CLI 步骤**：用户已明确纯点击口径；`docs/部署指引_纯点击.md` 是部署步骤唯一出处，README 只做索引。
- **不许给成本机制加定时 / 轮询 / 遍历**（B1-3）：不加 `scheduled`、Cron Trigger、DO alarm、`setInterval`、每次请求查用量、GraphQL 用量轮询、R2 `list()` 对账。历史教训是一个定时遍历 alarm 一天烧爆 DO 免费读写；核算只在写口做，沙盒静态断言会拦回潮。
- **不许把「拿不到可信数字」改成放行**（B1-3）：D1 聚合失败、旧版令牌缺 `declaredTotalBytes` / `bucketCapBytes`、`head().size` 不可用、容量配置不可信，一律 503 / 413 拒绝。这是「宁停不烧钱」的硬要求，不是可以优化掉的保守。
- **不许让 `upload_locks` 预留量自动过期或被定时清理**：预留只增不减是刻意的保守；删掉它等于让「上传中途放弃」的 R2 对象不被计入容量锁。清理只能由用户在 D1 Studio 手动确认后做。
- **不许给 R2 桶加「N 天后删除对象」生命周期规则**：本库是永久资料库，删对象会让 D1 索引还在但资源 404；只保留未完成分片上传的清理（桶默认 7 天，可收紧到 1 天）。
- **不许把 R2 换成 `r2.dev` 开发域对外**：官方明确它不支持 WAF / 缓存 / 访问控制，用它会让第 8 步的成本控制全部失效。
- **不许把对话内硬盘体系写进仓库 / 交付物 / 本档案，也不许清理 / 删除 / 打包交付窗口工作区**（v2，v7 澄清）：`INDEX.md` / `rounds.md` / `facts.md` / `decisions.md` / `pending.md` 只在窗口内的工作区，不进补丁包、不 `present_files`、不写进 §0 或 §9；**但窗口结束始终留存备查、不清理、不删除，也不需要产出工作区文件包交付给用户**（用户 v7 收尾明示）。它的职责是**替档案挡住过程细节**，写进来就等于把污染又送回跨对话载体。
- **不许在中间交互迭代档案**（v2）：除用户明示的收尾 / 专项迭代外，不改 §0、不记 §9、不升版本。每次交互都写会把窗口内的过程细节固化下来，正是 §0.11 要避免的。
- **不许让下个窗口读取 / 继承上个窗口的硬盘体系**（v2，v7 澄清措辞）：旧工作区**留存备查、不清理、不删除**，但**不纳入后续窗口**（不读、不继承、不交付）；新窗口按 §0.11 从档案重建一份干净的。跨对话只认**当前参考版本**那一份档案。「窗口结束即作废」是旧表述，按「留存备查 + 不纳入后续窗口」理解，见 §0.11。

> | **一轮 / 每轮对话** | **一个对话窗口**（框架 F3 口径，用户 2026-11-19 澄清）；**不是一次交互**。窗口内可有多次交互、可批量反馈 |
> | 一次交互 / 一次沟通 | 窗口内的一次来回 |
> | **开场交互** | 窗口内第一次交互：读档案 + 建硬盘体系 |
> | **中间交互** | 窗口内其余交互：只滚硬盘、不动档案 |
> | **收尾交互** | 窗口内最后一次交互（用户明示）：迭代档案、做跨对话准备 |
>
> v2 里的「中间轮 / 收尾轮」按此表统一为「中间交互 / 收尾交互」。**框架 F3 现行语言表述把「每轮对话」用得像「每次交互」，待下次迭代框架时统一改为「每个对话窗口为一轮」**（通用资产，本轮不动；提醒见 §5）。
> 本机制由用户在 B1-4 轮确认，作为本项目协作基线长期沿用（框架 §10.5 候选经验 C-01，**项目内已采用**；通用手册回写待 E 段）。

**为什么**：上下文「爆内存」后靠记忆复述会漂移 —— 数字、口径、已否决方案最容易抄错；单次对话做不完 / 意外中断时需要无损接续。但把窗口内的过程细节写进档案，会污染下个对话、增加启动负担。所以：**细节只留在窗口内，结论才进档案**。

**开场交互 · 先读档案，再建硬盘**
1. 读用户上传的**唯一一份当前参考版本档案**（§0 优先；`docs/` 里旧版不用管），从公开仓库拉代码（主路径，不用用户再传）。
2. 在**仓库目录之外**的工作区新建本窗口硬盘体系 —— **不进仓库、不打包交付、不纳入后续窗口**（但**始终留存备查、不清理、不删除**，见下方「留存与接续」）：

| 文件 | 装什么 | 何时读 |
|---|---|---|
| `INDEX.md` | 边界声明、本窗口时间线、条目索引、读写协议 | **每次交互开场必读** |
| `rounds.md` | 各轮增量：改了什么、为什么、当时结论与取舍 | 需要回溯时 |
| `facts.md` | 本窗口精确数字 / 配置值 / 已核实官方口径速查 | 引用数值前 |
| `decisions.md` | 口径速查 + 已否决方案（防把旧方案捡回来） | 改代码 / 改文档前 |
| `pending.md` | 未决 / 未验 / 下一轮第一步 | **开场与收尾必读** |

3. 开场只读 `INDEX.md` + `pending.md` + `rounds.md` 最近一轮，三份就够起手；**用到才查** `facts.md` / `decisions.md`。不把缓存全文复述进回复，不一次塞回上下文。

**中间交互 · 只滚硬盘，不动档案**：每次交互收尾更新 `rounds.md` / `pending.md` / 时间线；数字变了才改 `facts.md`，口径变了才改 `decisions.md`。**不写档案、不改 §0、不记 §9**。攒批是漂移来源，但这里补的只是本窗口自己的备忘。

**收尾交互 · 才做跨对话准备**：窗口内最后一次交互（由用户明示「收尾 / 迭代档案 / 下个窗口前」触发；**模型不自行预判哪轮是最后**）才迭代档案，把本窗口的**决策、成果、口径变化、未验项**收进 §0 / §9，作为下个窗口启动基础。**只带结论，不带过程细节与数值副本**。

**留存与接续（v7 用户澄清的标准口径）**：窗口结束 → 硬盘体系**始终留存备查、不清理、不删除、不打包交付**（用户不需要、也不应收到「工作区文件包」）；「作废 / 不跨对话」只指**不纳入后续窗口** —— 下个窗口**不读、不继承**，按「开场交互」从**当前参考版本档案**重建一份干净的。同一窗口意外中断 → 读原硬盘体系即可**无损接续**（这正是它的主要用途）；用户若在新窗口需要回溯旧窗口细节，可明确指定「查上一窗口硬盘」，届时按该条提供。**v5 / v6 补记曾把「保留不清理」写成「一次性例外」，属表述不准**：v7 起把它定为通用规则，并把框架 F3 / 模板 T3 里「窗口结束即作废」一类措辞登记为 **E 段**修正项（见 §5 提醒块）。

**由此确立的开发节奏**：窗口内可放心**批量反馈信息**；但**一次对话解决一个问题、进行一次部署测试**，逐步开发。反馈批量 ≠ 一次改一堆东西；收敛到单一问题，验完再进下一个，配合「区分沙盒已验 / 真机未验」与「一轮反馈 ≤3 条」防范围膨胀。

> **★ 档案版本判据（v3）**：迭代档案＝**新增一个版本号文件**，旧版**不删、不覆盖**；上传时**增加就可以**。所有相关文件只注明「当前参考 vN」。S1 完成后由用户手动归档旧版到 `docs/archive/`。
>
> **判据（记住这一条就不会做反）**：判断一份东西该不该落盘，先问「它要不要被下个对话读到」。要 → 只写进**当前参考版本**档案；不要、但本窗口后面还要用 → 写进窗口内硬盘（**留存备查、不清理，但不纳入后续窗口**）；都不要 → 不写。窗口内硬盘**不打包交付给用户**。

## 1. 目标与验收标准

**一句话目标**：做一个公开只读的网页版 TRPG 模组库，上传者在受保护入口提交主控台、思维导图和资源包后，浏览端自动上架该模组；访客点进条目即可分别查看思维导图与主控台，主控台内的原文与地图等链接自然取到对应文件。

**必须做到**：
1. 浏览端公开只读，按 `system` 分大区、DND 下按 `kind` 细分；卡片 → **条目页**，条目页并列「思维导图 / 主控台」两个入口，入口 URL 由索引里两个原始文件名拼出。
2. **点「思维导图」→ 浏览器内直接预览 `.xmind`**：预览页 fetch R2 原文件 → 解 ZIP → 只读画布渲染，支持缩放 / 平移 / 折叠 / 多 sheet 切换；不跳下载、不依赖本地装 XMind。
3. 上传端受 Cloudflare Access 保护，**三区输入**：① 主控台单文件 ② 思维导图单文件（两者平铺在条目根目录）③ 其余文件与文件夹**直接拖拽上传并维持原有文件夹格局**；加表单字段，提交后浏览端**即时**出现新条目。
4. 资源路由随模组自动适配（slug 前缀 + 剥顶层后的包内相对路径），不同模组地址不同无需逐条写映射；**资源包只用于支撑主控台内链接，不在浏览端列举或推送**。

**明确不做**（边界，比「要做」更重要）：
- 不做中文搜索 / 全文检索 / 搜索输入框（原因：交互定为纯点击-查看型）
- 不做登录、评论、用户系统（原因：浏览端公开只读，唯一写口在 Access 后的上传端）
- **不在浏览端列资源包清单、不推送资源文件、不把资源渲染成卡片**（原因：A-1b 明确——资源包只为让主控台内链接落到正确内容；入口只在主控台里）
- **不摊平、不重命名拖拽树，不把所选顶层文件夹名多挂一层**（原因：A-1c 明确要维持整理时的目录格局；多一层会让主控台内 `assets/...` 相对链接断掉）
- 不做上传时对 HTML 引用的自动重写与 ASCII 改名（原因：上传成功与内容被改混在一起，追不到真实写入；Worker 运行时非 Node，三层校验跑不了）
- **不生成第二份预览产物（导出 HTML/SVG）、不在上传端解析 xmind、不在 Worker 里解析 xmind**（原因：解析放访客浏览器，原文件是唯一真值；Worker 有 10 ms CPU / 3 MB 限额，上传端导出会养派生副本）
- **预览只读，不提供编辑、保存、写回**（原因：浏览端公开只读）
- 不做构建期静态生成分类页（原因：选运行时索引，避免上架空窗）
- 不重绘 / 不重写主控台内部版式与美术（原因：样板原样托管）

**验收标准**（可量化，一句话判定过没过）：
- 上传一条目 → 浏览端首页卡片数 **+1**，对应 `system` / `kind` 分类页命中
- 点卡片 → **条目页出现且仅出现两个入口**：思维导图、主控台；点主控台 → 正常打开，内部 iframe / 原文（单文件或多文件）/ 地图链接**全部可达**，无空白 iframe
- **点「思维导图」→ 浏览器内出现可读导图**（不是下载、不是空白、不是「请安装 XMind」）；节点标题可见，缩放 / 平移 / 折叠可用；多 sheet 有切换
- **两代格式**：用一份 XMind 2020+（`content.json`）与一份 XMind 8（`content.xml`）样本各验一次，均出图；只读占位 `content.xml` 导致空图视为未通过
- **解析失败兜底**：加密 / 损坏 / 未知格式 → 可见错误提示 + 「下载原文件」链接，**不留白屏、不静默空白**（**v6 口径**：用户 2026-11-24 决定**本项不再列为验收项**、不再构造坏样本测试；代码兜底保留不删，真机未触发。S1 收尾并回 §1–§8 时统一删改本条）
- **两入口 URL 分别等于索引 `consoleFile` / `mindmapFile`**，不硬编码 `console.html` / `mindmap.xmind`；中文文件名原样保留
- **拖含 ≥2 层子目录的资源树 + 两个单文件** → R2 key 层级与本地一致、**顶层文件夹名不被挂成额外一层**；主控台内深层相对链接（含中文／特殊字符）全部可达
- **单文件区与拖拽树同名（或两单文件同名）→ 拒上架并回执**，索引不变；不静默覆盖
- **浏览端不出现资源包清单、不主动推送资源文件**；资源仅由主控台内链接按需加载
- 包内缺任一**被主控台实际引用**的本地文件 → **上架被拒并回执**，索引不变（空值路径单独跑）；**不预设必备文件名清单**；树内多余的未被引用文件不拦
- **B1 无真实 xmind 样本时用占位文件验「入口可达 + 失败兜底」，不算未通过**；渲染保真度留待用户本地真实样本验
- `status: draft` 条目不出现在浏览端列表
- 非法 `system` / `kind` 枚举 → Worker 拒绝，索引不变
- 上传端未过 Access → 403；浏览端匿名可读
- 浏览端无搜索框、无文本输入交互，纯点击可达全部条目
- 单次上架**不消耗 Pages 构建**；浏览端首屏只拉一次列表 API（预览页的 xmind fetch 属按需，不计首屏）
- 体积 / 性能：单 Worker 合并不超 3 MB / 10 ms CPU / 50 subrequest；预览库在静态壳不占 Worker 限额；资源大包走预签名直传不经 Worker 请求体

> 验收按手册验收清单**六层**走：功能 / 视觉反馈 / 静默失效 / 规范合法 / 体积性能 / 交付；带后端项目加验分层表。
> 「只能真机 / 等时间」的层按 §0.6 登记，不当作未通过。

## 2. 已定决策（不要再重新讨论）★

| 决策项 | 结论 | 理由 |
|---|---|---|
| 技术选型 | 浏览端静态壳 + **单 Cloudflare Worker** + **R2**（资源）+ **D1**（索引）+ **Cloudflare Access**（上传端） | 上架低频、浏览高频；复杂度压在低频侧，高频侧保持 CDN 直出 |
| 主选路线 | **运行时索引**：Worker 写 D1，浏览端拉 `/api/modules` 即时渲染 | 无构建空窗、无 GitHub 写凭据、不吃 500 次/月构建 |
| 风险偏好 | 保守：宁可功能少也不出「上传成功但页面没变」的静默失效 | 手册原则 2 / 8 |
| 部署方式 | 公开 GitHub 仓库 + Cloudflare；Worker 走 `wrangler.toml`，浏览端静态壳同一项目 | 框架主路径，代码可由平台拉取 |
| **交付形态** | **带后端**：仓库根 `wrangler.toml` + Worker 入口 + R2/D1 绑定 + 静态壳产物目录 | 手册 6.3「带后端项目」；**不套**单文件 `index.html` |
| 索引存储 | D1 一条目一行（upsert） | 避免覆盖式写一份大 JSON 造成并发上架丢更新 |

> ⚠️ **适用边界**：「单文件 / 零构建 / `index.html`」是纯前端静态站口径，不是通用默认值。本项目属**第三形态：带上传 Worker 的静态壳 + 运行时索引**，手册 / 模板现有两栏都不贴合，已登记为项目内一次性增补草案（见 §3.2、§0.6），**不动 H3/F3/T3 现行版**。

**额度事实**（2026-11-18 联网核实自 Cloudflare 官方文档，**仅作选型输入，非边界**）：Workers Free 10 万请求/天、**仅 1 个 Worker 脚本**、3 MB / 128 MB / 10 ms CPU / 50 subrequest；R2 10 GB-month、Class A 100 万次/月、Class B 1000 万次/月、出口免费；D1 500 万行读/天、10 万行写/天、5 GB；Pages 500 构建/月、1 并发、2 万文件、单文件 25 MiB、100 自定义域名；Zero Trust / Access Free 覆盖 50 用户。

### 2.1 已否决方案 ★（一行成本，防止新对话重提）

| 被否决的方案 | 否决理由 |
|---|---|
| 纯静态零后端 + 本地生成器产「可提交一包」由用户 push | 与「上传完浏览端自动更新」直接冲突，多一次手工动作 |
| Worker 写回 GitHub 触发 Pages 重建（Astro + Content Collections + Pagefind） | 上架有 1–3 分钟空窗、Worker 要存 GitHub 写凭据、每次吃 1 次 500/月构建；且 Pagefind 本就索引不到译文成品 HTML，「白得搜索」不成立；用户已明确不做中文搜索，优势归零 |
| 浏览端运行时渲染 + D1 FTS 中文全文搜索 | 需求已砍，不做 |
| **浏览端列资源包清单 / 主动推送资源文件 / 把资源渲染成卡片** | A-1b 明确：条目页只给思维导图 + 主控台两入口，资源入口只在主控台里；列清单会让条目页退化成资源管理器，且与「原样托管主控台」重复 |
| 上传时确定性重写 HTML 互引 + 三层校验 | 上传成功与内容被改混在一起；Worker 运行时非 Node，结构 / `node --check` / DOM mock 三层跑不了；整包相对路径原样放已够用 |

**接口契约（关键结论，BC 段照此实现）**
- 上传表单字段：`title` / `system` / `kind` / `summary`（可选）/ `cover`（可选）/ `status`；`slug` 由英文小写短横线生成，作为资源前缀与索引主键
- **上传端三区**：① 主控台单文件 → `consoleFile = File.name` ② 思维导图单文件 → `mindmapFile = File.name` ③ 其余文件／文件夹拖拽树 → 每项带 `relativePath`
- **`relativePath` 规则**：`webkitdirectory`（推荐，最稳）或 drop 的 `webkitGetAsEntry()` 递归取得；若第一段 == 所选顶层文件夹名则**剥掉该段**（`split('/').slice(1).join('/')`），散拖文件保持自身文件名；不改名、不摊平
- **R2 key** = `modules/<slug>/<剥顶层后的 relativePath>`；两个单文件 key = `modules/<slug>/<原始文件名>`。R2 无目录对象，子目录只是 key 前缀，天然保住格局；空目录不产生对象（浏览端本就不列清单，无影响）
- `GET /api/modules` → 已发布条目列表（含 `slug` / `title` / `system` / `kind` / `cover` / 资源基址 / **`consoleFile` / `mindmapFile`**），供静态壳渲染卡片与分类；**返回体不含资源包清单**
- 条目页只渲染两个入口：`思维导图` → **预览页 `web/mindmap.html?slug=<slug>`**；`主控台` → 基址 + `consoleFile`；**不渲染资源列表**
- **思维导图预览链路**（不经过 Worker）：预览页 `GET /api/modules` 拿到 `mindmapFile` → 拼 `https://<R2 域>/modules/<slug>/<mindmapFile>` → `fetch` 取 `ArrayBuffer` → `fflate`/`JSZip` 解 ZIP → **优先 `content.json`，不存在才回退 `content.xml`**（新版文件里的 `content.xml` 只是「请升级」占位，读它会得到空图）→ `@mind-elixir/import-xmind` 转节点树（覆盖 JSON 现代格式 + XML 旧格式）→ `mind-elixir` 只读画布；多 sheet 用 tab 切换；**不写回、不生成第二份产物**
- **解析失败兜底**：加密（XMind 密码保护会加密内容）/ 损坏 / 未知格式 / fetch 失败 → 显示可见错误 + 「下载原文件」链接；**不留白屏**。`Content-Disposition` 让该兜底链接触发下载
- **R2 CORS**：bucket policy 同时允许浏览端 origin 的 `GET`（预览页 fetch）与预签名 `PUT`（上传直传）；自定义域名连接 CORS policy 后会自动返回 CORS 响应头，请求需带 `Origin`
- **格式事实**（2026-11-18 联网核实，XMind 官方文档 / 格式文档 / 开源解析器 README）：`.xmind` 是标准 ZIP；XMind Zen / 2020+ 主体在 `content.json`（sheets 数组、`rootTopic`、`children.attached` / `detached`、独立 relationships），XMind 8 及以前在 `content.xml`；另有 `metadata.json` / `manifest.json` / `Thumbnails/thumbnail.png` / 可选 `resources/`；MIME 为 `application/vnd.xmind.workbook`。**预览定位＝结构可读预览**，不承诺等同客户端 100% 还原
- **备选实现（未采用，改动前须先说明利害）**：XMind 官方 `xmind-embed-viewer`（MIT，`viewer.load(arrayBuffer)` 几行即可、`sheets` / `setZoomScale` / `setFitMap` 现成、`region:'cn'` 切 xmind.cn）；但 iframe 依赖 XMind 远端资源、最新发布停在 2023，多一个外部可用性依赖
- 上架前校验：解析主控台全部本地 `href` / `src` / `iframe src`，**依赖集合 = 两单文件原始名 + 拖拽树 `relativePath` 集合**，按实际引用路径逐项求包含；缺一即拒并回执、索引不写；**不预设必备文件名清单**（原文可能是单文件，也可能是若干文件）；树内多余未被引用文件不拦
- **重名冲突**：单文件区与拖拽树同名、或两单文件同名 → **拒绝上架并回执**，不静默覆盖
- 绝对外链（`media.dndbeyond.com` 等）保持不动，不纳入存在性断言；根相对 `/...` 路径属 §0.6 未验风险，验出后再定
- 枚举由 Worker 内 zod 强校验；`draft` 不进 `/api/modules` 返回
