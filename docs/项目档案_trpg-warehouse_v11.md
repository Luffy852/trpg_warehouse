### 0.4 已定口径（用户拍板，不要擅自改）

| 域 | 结论 |
|---|---|
| 项目性质 | 内容库 / 线上站点；≠ 本地 `ttrpg-module-prep`（生产工具 / 模板库），后者留在本地不改造 |
| 访问模型 | 浏览端**公开只读、不设访问限制**；上传端用 Cloudflare Access 保护。前端两个，同域隐藏路径 `/upload` |
| 交互形态 | 纯点击-查看型；**不做中文搜索 / 全文检索 / 搜索输入框** |
| 后端 / 存储 / 索引 | 单个 Cloudflare Worker（Workers Free 仅允许 1 个）；资源包 → **R2**（自定义域名公开读、CDN 缓存、出口免费）；索引真值 → **D1**（一条目一行、upsert）；**运行时索引**，上传后浏览端即时自动更新、不等构建、不手工 push |
| 条目呈现模型 | 一个模组＝卡片 → **条目页并列「思维导图 / 主控台」两入口**；入口 URL 由 D1 的 `consoleFile` / `mindmapFile` 原始文件名拼出，不硬编码、中文名原样保留 |
| 资源包角色 | **不是浏览端可见实体**：不列清单、不推送、不渲染成卡片／下载列表；入口只在主控台里。资源文件公开可读，但只为让主控台内链落到正确内容 |
| 原文形态 | 可能是单一文件也可能是若干文件，外加地图等；形态不固定 → 上架校验**不预设必备文件名清单**，只按主控台实际引用的本地路径逐项断言 |
| 上传端输入 | 三区：① 主控台单文件 ② 思维导图单文件（两者平铺条目根）③ 其余文件与文件夹直接拖拽。根＝`/modules/<slug>/` |
| 拖拽目录语义 | 浏览器读 `webkitRelativePath`，**整棵树连子目录保留**，不摊平 / 不重排 / 不改名；**剥掉所选顶层文件夹名**，其内容挂 slug 根（否则 `assets/xxx.png` 会多一层而断链）。散拖文件保持自身文件名。R2 无目录对象，目录只是 key 前缀 |
| 路由适配 | R2 key＝`modules/<slug>/` + 剥顶层后的 `relativePath`；绝对外链不动；**不做 ASCII 重命名、不做上传时引用重写**。根相对 `/...` 属 §0.6 留登记 |
| .xmind 查看形态 | **浏览器内只读预览**（A-1d 覆盖早期「下载打开」）：预览页 fetch R2 → 解 ZIP → 优先 `content.json`、回退 XMind 8 `content.xml` → `@mind-elixir/import-xmind` → `mind-elixir` 只读画布；缩放 / 平移 / 折叠 / 多 sheet；**不编辑保存、不生成第二份 HTML/SVG 副本、不在 Worker／上传端解析**。原文件是唯一真值。失败给可见提示 + 下载兜底 |
| .xmind 平台限制 | 元宝收不到 `.xmind` **不影响开发／功能**：链路只把它当文件对象，解析发生在访客浏览器。仅影响 B1 真实样本冒烟与保真度实测 |
| 预览缩放 | **B 方案**：保留库默认全端通路互不干扰，只把 `scaleSensitivity` 1 → 0.1 并改状态行文案；**不自定义 `handleWheel`、不改 `scaleMax` / `scaleMin`**。两代 xmind 共用同一份代码 |
| 分类枚举 / 判据 | `system: dnd\|coc\|other`；DND 下 `kind: campaign\|module\|encounter`；`status: draft\|published`。**人工语义判定、不可自动猜**；不加 `series` / `sessions` |
| 样板 / 版权 | 样本模组只作呈现形式与美术风格参照，首批传哪个不重要；成品 HTML 原样托管、站点不重绘主控台。中文译文「非官方粉丝翻译 / 禁商用 / 保留译者声明」与第三方声明在公开站原样保留，**不因版权设访问限制** |

## 1. 目标与验收标准

**一句话目标**：公开只读的网页版 TRPG 模组库；上传者在受保护入口提交主控台、思维导图和资源包后，浏览端自动上架；访客点进条目即可分别查看思维导图与主控台，主控台内原文与地图等链接自然取到对应文件。

**必须做到**（决策点，非流水）：
1. 浏览端公开只读，按 `system` 分大区、DND 下按 `kind` 细分；卡片 → 条目页 → 仅「思维导图 / 主控台」两入口，URL 由索引两个原始文件名拼出。
2. 点「思维导图」→ **浏览器内直接预览 `.xmind`**（fetch R2 → 解 ZIP → 只读画布）；不跳下载、不依赖本地 XMind。
3. 上传端 Access 保护，**三区输入**（两单文件平铺条目根 + 其余文件／文件夹整树拖拽、维持目录格局）；提交后浏览端**即时**出现新条目。
4. 资源路由随模组自动适配（slug 前缀 + 剥顶层后的包内相对路径）；**资源包只用于支撑主控台内链接，不在浏览端列举或推送**。

**明确不做**（边界）：
| 不做 | 决策理由 |
|---|---|
| 中文搜索 / 全文检索 / 搜索输入框 | 交互定为纯点击-查看型 |
| 登录、评论、用户系统 | 浏览端公开只读，唯一写口在 Access 后的上传端 |
| 浏览端列资源包清单 / 推送资源文件 / 渲染成卡片 | A-1b：资源包只为让主控台内链接落到正确内容；列清单会让条目页退化成资源管理器 |
| 摊平 / 重命名拖拽树、保留所选顶层文件夹名为一层 | A-1c：要维持整理时目录格局；多一层会让 `assets/...` 相对链接断掉 |
| 上传时自动重写 HTML 引用与 ASCII 改名 | 上传成功与内容被改混在一起，追不到真实写入；Worker 运行时非 Node，三层校验跑不了 |
| 生成第二份预览产物（HTML/SVG）、上传端 / Worker 解析 xmind | 解析放访客浏览器，原文件唯一真值；Worker 有 10 ms CPU / 3 MB 限额，导出会养派生副本 |
| 预览可编辑 / 保存 / 写回 | 浏览端公开只读 |
| 构建期静态生成分类页 | 选运行时索引，避免上架空窗 |
| 重绘 / 重写主控台内部版式与美术 | 样板原样托管 |

**验收结论**：V-01～V-13 **全部真机闭环**（W1 / W2-a / W2-b / W2-c / W3 / D 段逐层收口，详见 §6.2）。
**已按最终结论删改**：A-12「加密 / 损坏 / 未知格式解析失败兜底」**不再列为验收项**（v6 用户拍板；代码兜底保留、真机未触发）；
旧版 XMind 8 真实样板按用户决定不补、登记「未验 · 缺样本」，`content.xml` 回退能力保留。
验收按手册**六层**（功能 / 视觉反馈 / 静默失效 / 规范合法 / 体积性能 / 交付）+ 带后端分层表；
「只能真机 / 等时间」的层按 §0.6 登记，不当作未通过。

**接口契约（关键结论，未来开发照此实现）**
- 表单字段：`title` / `system` / `kind` / `summary`（可选）/ `cover`（可选）/ `status`；`slug` 由英文小写短横线生成，作为资源前缀与索引主键；`isUpdate`（缺省 false）。
- 上传端三区：① 主控台 → `consoleFile = File.name` ② 思维导图 → `mindmapFile = File.name` ③ 其余文件／文件夹拖拽树 → 每项带 `relativePath`。
- `relativePath` 规则：`webkitdirectory`（推荐）或 drop 的 `webkitGetAsEntry()` 递归取得；若第一段 == 所选顶层文件夹名则**剥掉该段**；散拖文件保持自身文件名；不改名、不摊平。
- **R2 key** = `modules/<slug>/<剥顶层后的 relativePath>`；两个单文件 key = `modules/<slug>/<原始文件名>`。子目录只是 key 前缀；空目录不产生对象。
- `GET /api/modules` → 已发布条目列表（`slug` / `title` / `system` / `kind` / `cover` / 资源基址 / `consoleFile` / `mindmapFile`）；**返回体不含资源包清单**；`draft` 不进返回。
- 条目页只渲染两入口：`思维导图` → `web/mindmap.html?slug=<slug>`；`主控台` → 基址 + `consoleFile`。
- **思维导图预览链路（不经过 Worker）**：`GET /api/modules` 取 `mindmapFile` → 拼 `https://<R2 域>/modules/<slug>/<mindmapFile>` → `fetch` ArrayBuffer → `fflate` 解 ZIP → **优先 `content.json`、不存在才回退 `content.xml`**（新版文件里的 `content.xml` 只是「请升级」占位，读它会得到空图）→ `@mind-elixir/import-xmind` → `mind-elixir` 只读画布；多 sheet 用 tab 切换；**不写回、不生成第二份产物**。
- **解析失败兜底**：加密 / 损坏 / 未知格式 / fetch 失败 → 可见错误 + 「下载原文件」链接，不留白屏；**代码兜底保留**（v6 起不再列为验收项）。
- **R2 CORS**：bucket policy 同时允许浏览端 origin 的 `GET`（预览页 fetch）与预签名 `PUT`。
- **格式事实**：`.xmind` 是标准 ZIP；XMind Zen / 2020+ 主体在 `content.json`（sheets / `rootTopic` / `children.attached` / `detached` / 独立 relationships），XMind 8 及以前在 `content.xml`；预览定位＝**结构可读预览**，不承诺等同客户端 100% 还原。
- **备选实现（未采用，改动前须先说明利害）**：XMind 官方 `xmind-embed-viewer`（MIT，几行代码、现成 API），但 iframe 依赖 XMind 远端资源、最新发布停在 2023。
- 上架前校验：解析主控台全部本地 `href` / `src` / `iframe src` / `poster` / `data-src`，**依赖集合＝两单文件原始名 + 拖拽树 `relativePath` 集合**，按实际引用路径逐项求包含；缺一即拒并回执、索引不写；**不预设必备文件名清单**；树内多余未被引用文件不拦。**范围钉死**，扩展到 CSS `url()` / `@import` 属 §2.2 扩张型、已评估不实施。
- **重名冲突**：单文件区与拖拽树同名、或两单文件同名 → **拒绝上架并回执**，不静默覆盖。
- 绝对外链保持不动、不纳入存在性断言；根相对 `/...` 属 §0.6 留登记。枚举由 Worker 内 zod 强校验。

### 3.3 贯穿全程的方法论

1. 先定位根因再动手；验证环境的严格程度要高于用户实际环境。
2. 不只看「没报错」，要断言「该发生的确实发生了」（上架＝卡片 +1 / 更新＝卡片数不变且内容已更新）。
3. 同一件事只在一处写：索引真值唯一、路由由 slug 推导、不养派生副本；**所有「看起来对的数字」都要能追到真实写入**。

**已知局限（明确告知，不夸大能力）**：不做中文搜索，条目多了只能靠分类点击找；预览是「结构可读预览」，复杂样式可能简化、不等同 XMind 客户端 100% 还原；`.xmind` 加密文件打不开只能走下载兜底；元宝侧收不到真实 `.xmind`，两代格式与保真度须由用户本地真实样本验；根相对路径 / 中文路径编码属 §0.6 留登记；上传成功后浏览端即时可见依赖 D1 写入成功，靠行为断言兜住。
